# x_accounts_latest_full.json — Structure Reference

Location: `${HERMES_HOME}/cron/data/x_accounts_latest_full.json`

Generated by `fetch_x_accounts.py` (cron job `x-accounts-scan`, schedule `30 22 */2 * *`).

## Top-level Keys

| Key | Type | Description |
|-----|------|-------------|
| `generated_at` | ISO timestamp | When the scan ran |
| `new_posts` | array | New (non-duplicate) posts found |
| `errors` | array | API errors encountered |
| `scan_meta` | object | Budget and cursor info |

## scan_meta Fields

```json
{
  "request_budget": 12,        // Max X API requests per run
  "x_api_requests_attempted": 12,
  "tracked_accounts": 84,      // Total accounts in x-accounts.yaml
  "accounts_selected": 12,     // Accounts chosen this run (round-robin)
  "accounts_scanned": 12,
  "accounts_skipped_budget": 72,
  "user_cache_size": 84,
  "cursor_start": 9,           // Round-robin cursor position
  "cursor_next": 21            // Next run starts here
}
```

**Budget note**: Only ~12 accounts scanned per run out of 84 tracked. The cursor advances each run, so all accounts are covered over ~7 runs (14 days at 2-day schedule).

## Dedup State

Processed posts are tracked in `${HERMES_HOME}/.hermes/processed_x_accounts.json` (not at cron/data level). The `fetch_x_accounts.py` script handles dedup before writing `x_accounts_latest_full.json`.

## User IDs Cache

`${HERMES_HOME}/cron/data/x_accounts_user_ids.json` — Maps handles to X user IDs, refreshed on scan. Avoids redundant API lookups.
