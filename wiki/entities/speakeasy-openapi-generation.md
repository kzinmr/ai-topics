# Speakeasy OpenAPI Generation

## TL;DR

**Speakeasy** open-sourced its full OpenAPI code-generation suite (SDK generators, agent-native CLI generator, documentation MCP server generator) under **AGPLv3** in September 2026, in partnership with **Google DeepMind**. The suite powers Google's new GenAI SDKs (Interactions, Agents, Webhooks APIs). The trigger: in May 2026, the proprietary SDK generator Google previously used was acquired and abruptly shut down right before Google I/O — a case study in the platform risk of closed generator tooling.

## Background: The May 2026 Shutdown Incident

Google's account (Google Developers Blog, Sep 17, 2026, by Amir Hardon & Philipp Schmid):

- For years the frontier AI ecosystem, Google included, relied on specialized proprietary tooling to generate client libraries handling streaming protocols, strict error hierarchies, and rich type unions.
- In **May 2026** — right before Google I/O and the GA of the Interactions API — that provider **was acquired and abruptly announced its shutdown**.
- Lesson drawn: if the industry standardizes on OpenAPI for interface definition, the tooling that compiles specs into client libraries, CLIs, and agent tools **should be open infrastructure**.

## What Was Open-Sourced (AGPLv3)

Repo: [speakeasy-api/openapi-generation](https://github.com/speakeasy-api/openapi-generation)

| Component | Description |
|-----------|-------------|
| Multi-language SDK generators | Client libraries for 7 languages (Python, TypeScript, Go, Java, C#, PHP, Ruby) with static typing, SSE streaming, retries, pagination |
| Agent-native CLI generator | Compiles standalone CLI binaries so **AI coding agents can run an API directly from terminal sessions** without throwaway HTTP scripts |
| Documentation MCP server generator | Turns OpenAPI specs + markdown docs into an **MCP server**, letting coding agents (e.g. Antigravity) query live, verified schemas instead of guessing outdated methods |

Licensing nuance: AGPLv3 applies to the generator itself; **generated code/SDKs remain owned by the user under any license** (MIT, Apache 2.0, ...). Modifications to the generator compiler must stay open.

## Determinism vs. Agents in SDK Generation

Google DeepMind's architecture choice is notable as a stance in the "AI writes everything" debate: transforming formal API specs into multi-language SDKs "demands determinism and strict type safety," so they pair a **fast, deterministic generator at the core** with **Antigravity AI agents accelerating only the custom parts** of the SDK. Headcount effect: previously handcrafted generators took multiple engineers; the new setup spans six targets with roughly one engineer.

## Significance for Agent Tooling

The suite is explicitly **agent-native**: CLIs and MCP servers are generated as first-class outputs alongside human-facing SDKs. This reflects the broader shift where API consumers increasingly include coding agents, and up-to-date machine-readable tool surfaces (verified schemas, terminal-runnable APIs) replace ad-hoc integrations.
