Today, we're introducing Browser Actions, a new capability that lets your Decagon agent access and complete tasks inside systems where there isn’t a traditional integration available.
Many of the systems that run a business weren’t designed with APIs in mind. Internal claims systems, partner portals, vendor dashboards, and more often expose only a login screen and a set of buttons. The only way to get anything done is to sit down and click through the flow manually.
Sometimes an integration is technically possible, but it lives behind a legacy, on-prem system that only the customer's own IT team can reach. Standing that up can stall a project for months, while the actual work still needs to happen by hand in the meantime.
Browser Actions gives your agent a way through computer use. It extends the agent you've already built so it can log in, navigate, and complete a task inside any system your team can access.
The same interface, no additional build
Browser Actions navigate a page directly. It reads what's on the screen, clicks the right element, types into the right field, waits for the next page to load, and keeps going until the task is done. Unlike a typical integration, which requires an engineering team to build a connection to a vendor's backend, Browser Actions uses the same website or application your team already logs into. It interacts with the same screens and buttons someone would manually click.
Take a customer reporting a lost or stolen account with a consumer banking business. The company's public support flow goes beyond a single form. It starts in the help center, routes into a contact form from there, and which screens show up next depends on the customer's answers along the way. Someone who says they've already filed a report gets routed to a different set of follow-up questions than someone who hasn't. The path isn't the same for every customer, so the number of steps to complete it isn't either.
With Browser Actions, your Decagon agent can now take action end-to-end on behalf of the customer. It reads the customer’s answers, picks the matching path, fills in each screen as it comes up, and submits the report, all without the customer ever leaving the chat or being pointed to a separate link to finish on their own.
Security at the core, without the need to pull in IT
Allowing an agent to take actions inside a system your company doesn't own raises the governance bar significantly higher than for managing internal systems.
Browser Actions runs inside the same security and compliance framework as the rest of Decagon, including SOC-2, GDPR, HIPAA, and CCPA. It runs in a secure, containerized, and fully audited sandbox, and is covered by the same guardrails your team has already reviewed and trusted for the rest of the platform.
Get full visibility into the agent’s actions
Every step your agent takes inside a system gets logged as it happens, including the page it was on, what it clicked or filled in, and what happened next. In the fraud example above, if a field it expects isn't there, or a screen doesn't load the way it should, the agent stops and flags exactly that step as the point of failure so that the conversation is escalated appropriately.
That precision matters even more with an agent navigating third-party interfaces. Trust comes from being able to see exactly what an agent is doing and why, and Browser Actions was built with that visibility.
Resolve what used to be out of reach
Tasks trapped behind manual workflows have historically required a ticket, a handoff, or a delay. Browser Actions closes that gap so your agent can complete the task directly in the same conversation, without anyone needing to leave the chat.
