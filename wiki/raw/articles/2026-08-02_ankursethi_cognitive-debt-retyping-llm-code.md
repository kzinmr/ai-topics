# Prevent cognitive debt by manually retyping LLM-generated code

Despite using coding assistants on personal projects, Ankur Sethi found that allowing a coding assistant to roam free leaves him with "colossal amounts of cognitive debt."

The core insight: just because a problem is boring doesn't mean you want to fully offload your understanding of the solution to a machine. When an LLM writes code that you don't fully understand, you accumulate cognitive debt — you own the code but don't own the understanding.

His solution: **manually retype every line of LLM-generated code.** Not copy-paste. Actually type it out character by character. This forces you to:
- Read and understand every line
- Notice when the LLM made questionable choices
- Internalize the structure and patterns
- Build genuine understanding rather than superficial familiarity

The process is slower but eliminates the "disoriented" feeling that comes from one-shotting features. It transforms AI from a code-generator into a teaching tool — the LLM proposes a solution, and retyping it forces you to understand why.

This connects directly to the "LLMs reward expertise" thesis: the people who benefit most from coding assistants are those who already understand what the code does and can critically evaluate it. Novices who copy-paste accumulate technical debt they can't pay down.
