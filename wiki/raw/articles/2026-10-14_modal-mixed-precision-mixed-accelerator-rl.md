# Toward RL on mixed-precision, mixed-accelerator samplers

Modal engineering blog, 2026-10-13. Extracted body of the post.

## Core question

In large-model RL, samplers (generation/rollout engines) usually run on the **same
accelerators and precision as the trainer**, keeping the two numerically close for stable
training. But serving systems outside RL freely optimize generation for speed/cost using
**low-precision formats (FP8, MXFP4, NVFP4)**, co-designed kernels, and accelerators built
just for long-context prefill. **Sampling already takes 80–85% of the GPUs in large RL runs**,
so this mismatch is a lot of cost left on the table. Can we run **mixed-precision,
mixed-accelerator samplers** (each running its own kernels) while keeping training stable and
performant?

## The two problems

1. **Learning.** Each serving optimization adds training–inference mismatch, making samples
   more **off-policy**, which destabilizes training. Natural solution: **off-policy correction**
   — lets a trainer learn from data generated by a different policy (as in stale samples in
   async training). It makes no assumption about *why* the policies differ, so it should apply
   equally to different precisions or accelerators.
2. **System.** RL infra is usually built around **homogeneous accelerator clusters**. Mixed
   samplers need the opposite: autoscaling accelerators that burst when needed and run with
   their own precisions/kernels. Solved with **serverless GPUs** on Modal.

## Setup

- Train **Qwen3.6-35B-A3B** (open-weight MoE) on agentic coding with up to **256K tokens** of
  context, using the **2.7K repository tasks Xiaomi released with MiMo-V2.6**, after removing
  repo history/traces that leaked the reference fix.
- Episode: model writes a patch for an issue over multiple turns, submits via a bash tool in a
  **Modal Sandbox**. Reward = 1 if the patch passes the task's tests in a fresh sandbox, else 0.
- Eval on **SWE-bench Pro V2** (no overlap with training set) + its hard subset **HARD-51**.
  Every checkpoint evaluated in BF16.
- Framework: **Miles** (RL framework) with **SGLang samplers** and a **Megatron-LM trainer**
  updating the policy in **BF16 on B200 GPUs**. Training fully **asynchronous, no staleness
  limit**; each update uses 128 prompts × 8 trajectories. Samplers keep their own
  accelerators/precisions/kernels; trainer does not replay their MoE routing decisions.

### The two sampler configurations

- **Mixed samplers** span **six kinds of accelerators**: B200 and B300 serve **NVFP4** weights;
  H100 and H200 serve **FP8 and BF16**; A100 and RTX PRO 6000 serve **BF16**. Each runs its
  accelerator's own kernels and keeps **KV cache in FP8**. A router assigns each agent session
  to one of **eight groups** in proportion to serving capacity.
- **Homogeneous samplers** run only on B200 with BF16 weights + BF16 KV cache (match the
  trainer; only kernels and staleness differ).

## Making mixed-sampler RL stable — three pieces (on top of GRPO)

Start from GRPO with no mismatch correction, then add:

1. **Masked importance sampling (MIS)** — multiplies each token's term by its importance ratio
   and **masks tokens whose ratio falls outside a fixed range**, so kept tokens follow the
   training policy and every ratio stays bounded. Without the mask, a few rarely-produced
   tokens with huge ratios dominate the update.
2. **Score centering (SC)** — removes drift by subtracting, at each position, the expected
   gradient of the log-probability under the sampling policy, so in expectation only advantage
   differences move the policy.
3. **Top-p sampling with mask replay** — keeps rare tokens out and gives both policies the same
   support: samplers sample each token only from the top-p candidate set (rare tokens with
   extreme ratios never enter the data); the trainer renormalizes its own probabilities over the
   same set.

## Result claim

With off-policy correction + autoscaling serverless GPUs, **stable, performant, and cheaper RL
is possible** with mixed-precision, mixed-accelerator samplers — demonstrated by training an
open-weight model fully asynchronously on agentic coding tasks.
