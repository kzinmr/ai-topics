# Warp Factories now works across Microsoft Teams and Azure DevOps

**Source**: [https://www.warp.dev/blog/warp-factories-microsoft-teams-azure-devops](https://www.warp.dev/blog/warp-factories-microsoft-teams-azure-devops)

Product
Warp Factories now works across Microsoft Teams and Azure DevOps
October 7, 2026
Warp Factories gives engineering teams the infrastructure to build, run, and improve software factories at scale. Define your factory as code, deploy agents and automations across your workflows, then measure, benchmark, and continuously improve how your factory performs.
Today, we’re bringing Warp Factories deeper into the Microsoft engineering ecosystem with the industry's first native support for both Microsoft Teams and Azure DevOps Services.
Put your factory to work from Microsoft Teams
Engineering work often starts in a conversation. Now, your factory can pick it up from there.
Mention the Warp app in a configured Teams channel or thread to delegate work with the conversation context attached. Your factory takes on the task, reports progress, and returns results to the same thread.
With Microsoft Teams, you can:
Delegate work by mentioning the Warp app in existing channels and threads
Trigger automations from mentions or channel messages
Keep context as work moves from conversation to implementation
Follow up in-thread as agents work through the task
Ship PRs back to your team for review
Read more about using Microsoft Teams with Warp Factories.
Run your factory from Azure DevOps Services
Azure DevOps is more than a code host for your factory. It can be a place where work starts.
@mention your factory from a work item or pull request, assign it work, or automatically trigger runs as events happen across your development workflow.
With Azure DevOps Services, you can:
@mention agents from work items and pull requests
Trigger automations from work item and PR events
Give each factory its own identity for Git and pull request operations
Work across selected repositories with scoped access
Ship pull requests back through Azure DevOps
And because these workflows are part of Factories as Code, your team can define integrations, agents, triggers, automations, and more as version-controlled configuration.
Read more about using Azure DevOps with Warp Factories.
