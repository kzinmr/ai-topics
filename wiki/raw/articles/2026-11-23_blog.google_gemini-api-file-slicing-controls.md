# Introducing file slicing controls in the Gemini API

Source: https://blog.google/innovation-and-ai/technology/developers-tools/file-slicing-controls/
Authors: Rohan Doshi (Senior Product Manager, Google DeepMind), Ben Caine (Principal Engineer, Google DeepMind)
Date: Nov 23, 2026

The Gemini API now features native file slicing controls, allowing developers to specify targeted pages, sheet ranges, and media segments for the model to load server-side. This capability reduces token costs for large files.

> Today, we're launching new file slicing controls in the API across Google AI Studio and Gemini platform, alongside native file upload support for Microsoft Office and OpenDocument formats. You can now pass PDFs, Office files (docs, slides, spreadsheets), audio, and video directly to the Gemini API and request only the pages, spreadsheet cells, media segments, and layers you need. This keeps context focused on the relevant parts of a file while **billing tokens only for the parts Gemini inspects**.

## Inspect only what you need

Real-world knowledge work lives in dense PDFs, slide decks, multi-tab workbooks, and long recordings. With server-side slicing, you do not have to flatten files to plain text or ingest entire files up front.

- **Upload once, slice across turns**: Upload a file once with the Files API and reuse its URI across turns and tool calls.
- **Give your agent control**: The API lets the agent specify what parts of a file to inspect directly inside a function response for faster and more efficient multi-turn workflows.
- **Skim cheap, then zoom in**: Skim first with extracted text, low-res previews, or transcripts, then spend high-resolution tokens only on the charts, dense layouts, and frames that matter.

Slice documents, spreadsheets, and videos and more by range, layer, resolution, and frame rate to control token usage.

## Make your harness multimodal without local bloat

> When model APIs only ingest whole files, agents end up running LibreOffice, PDF renderers, and ffmpeg inside the client harness to render and slice large files. This bloats memory, clutters local disk with extracted frames, and forces enterprise platforms to maintain per-user sandboxes just to slice files. With the Gemini API, pass a Files API URI on a user turn or directly inside a function response (`function_result`), and the API natively slices, renders, and tokenizes each file server-side the way the model was trained to see it.

## How it works

Native file slicing works across all Gemini 4 models, and existing file size and page limits still apply to the uploaded file. Processing options per media category:

- **Documents and slides** (PDF, Office and OpenDocument formats): page range (`start_page`, `end_page`), resolution (low/medium/high), content layers (`page_text` or `page_image`).
- **Spreadsheets** (.xlsx, .xls, .ods): worksheet tab (`sheet_index`), cell range (`visible_cells`), resolution, content layers (`data`, `formulas`, `visuals`).
- **Video**: clip time intervals (`start_offset`, `end_offset`), adjust fps and resolution (low/high), content layers (`transcript`, `frames`, `audio`).
- **Audio**: clip time intervals (`start_offset`, `end_offset`).

When processing options are omitted, documents and slides default to layout-preserving page images, and spreadsheets include evaluated values, formulas and sheet names across all tabs.

## Example: skim at a high level, zoom in on details

```python
from google import genai
client = genai.Client()
doc = client.files.upload(file="quarterly_report.docx")

# 1. Skim the whole document cheaply as extracted text.
skim = client.interactions.create(
    model="gemini-4-hydrogen",
    input=[
        {"type": "document", "uri": doc.uri, "mime_type": doc.mime_type,
         "processing": {"type": "static",
                        "page_options": {"content_layers": ["page_text"]}}},
        {"type": "text", "text": "Which page has the revenue bridge chart?"},
    ],
)
print(skim.output_text)

# 2. Zoom into the target page at high resolution (reusing the same URI).
detail = client.interactions.create(
    model="gemini-4-neon",
    input=[
        {"type": "document", "uri": doc.uri, "mime_type": doc.mime_type,
         "resolution": "high",
         "processing": {"type": "static", "page_options": {
             "start_page": 3, "end_page": 3, "content_layers": ["page_image"]}}},
        {"type": "text", "text": "Read the revenue bridge chart and footnotes on page 3."},
    ],
)
print(detail.output_text)
```

Gateway and SDK partners validated these controls ahead of launch, cutting prompt token spend directly in production harnesses.
