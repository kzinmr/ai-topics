# 대규모 언어 모델(LLM)과 활용 분야: 2부

**Source**: [https://cohere.com/ko/blog/llm-use-cases-p2](https://cohere.com/ko/blog/llm-use-cases-p2)

1부를 여기서 확인하실 수 있습니다.
여기
서 확인하세요.
대규모 언어 모델(LLM)을 처음 접하는 분들에게는 자연어 처리(NLP) 유스케이스에서 LLM을 언제, 어디에 사용해야 할지 파악하는 것이 다소 벅찰 수 있습니다. 이 블로그 시리즈에서는 Cohere의 LLM으로 해결할 수 있는 7가지 주요 유스케이스 카테고리를 정리하여 LLM 활용 방법을 쉽게 설명합니다.
시리즈의
1부
에서는 생성(Generate), 요약(Summarize), 재작성(Rewrite), 추출(Extract) 등 첫 네 가지 유스케이스 카테고리를 다뤘습니다. 이번 포스트에서는 검색(Search), 클러스터링(Cluster), 분류(Classify) 등 나머지 세 가지를 살펴보겠습니다. 마지막으로, 다양한 유형을 어떻게 조합하여 훨씬 더 흥미롭고 유용한 활용 사례를 만들 수 있는지 알아보겠습니다.
5. 검색/유사도(Search/Similarity)
LLM에 대해 언급할 때, 앞서 살펴본 네 가지 유스케이스에서 보았듯이 대부분 텍스트 생성 능력에 대한 논의가 주를 이룹니다. 상대적으로 덜 알려졌지만 그만큼 강력한 능력이 바로 텍스트 표현(text representation)입니다.
텍스트 생성이
새로운
텍스트를 만드는 것이라면, 텍스트 표현은
기존의
텍스트를 이해하는 것입니다. 오늘날 인터넷의 급격한 확산으로 인해 생성되는 비정형 텍스트 데이터의 양을 생각해보십시오. NLP 기반 자동화 기술이 없다면 인간이 이 방대한 양의 정보를 처리하는 것은 불가능할 것입니다.
텍스트 표현의 대표적인 유스케이스 중 하나가 유사도 검색입니다. 사용자가 텍스트 쿼리를 입력하면, 해당 쿼리와 가장 유사한 문서를 찾는 것이 목표입니다.
이 기능의 가장 대표적인 유스케이스는 검색 엔진입니다. 사용자는 검색 결과로 자신의 쿼리와 매우 관련성이 높은 링크와 문서를 기대합니다. 현대 검색 엔진이 매우 효율적으로 작동하는 이유는 단순히 키워드 일치를 넘어,
시맨틱 유사성
을 통해 쿼리에 적합한 결과를 매칭하는 능력이 뛰어나기 때문입니다.
쉽게 말해, 이들은 의미, 맥락, 주제, 아이디어 등 서로 다른 단어를 사용하더라도 밀접하게 연관된 추상적 개념을 기반으로 매칭을 수행할 수 있습니다.
예를 들어, 사용자가 “공항 지상 교통수단”이라는 검색어를 입력했다고 가정해 봅시다. 사용자가 택시, 렌터카, 기차 또는 기타 유사한 서비스를 명시적으로 언급하지 않더라도, 검색 엔진은 사용자가 이러한 서비스들을 찾고 있다는 것을 파악할 수 있어야 합니다.
텍스트 표현 모델에 텍스트 조각을 입력하면, 모델은 추가 텍스트를 생성하는 대신 입력 텍스트의 의미나 맥락을 나타내는 숫자 집합을 생성합니다. 이 숫자들을 “
텍스트 임베딩(text embeddings)
”이라고 합니다. LLM의 경우, 보통 수천 개에 달하는 매우 긴 숫자 시퀀스인 경우가 많으며, 시퀀스가 길수록 텍스트에 대한 더 많은 정보가 저장됩니다.
Cohere를 통해
Embed 엔드포인트
를 사용하여 이러한 유형의 모델에 액세스할 수 있습니다. 이 Python
노트북
은 시맨틱 검색 애플리케이션의 예시를 제공하며, 질문을 입력하면 검색 엔진이 해당 질문의 텍스트 임베딩과 가장 유사한 다른 자주 묻는 질문(FAQ)을 반환합니다.
또한 아래 이미지에 표시된 2차원 플롯에 모든 질문을 표시하며, 플롯에서 두 점이 가까울수록 의미론적으로 더 유사함을 알 수 있습니다.
상어와 박싱 데이에 관한 유사한 질문 두 가지 예시
이 개념은 훨씬 더 광범위한 사용 사례에 적용될 수 있으며, 예를 들면 다음과 같습니다:
조직 내 관련성 높고 유용한 문서 검색
유사 제품 추천
이커머스 제품 검색
읽기 기록 기반의 다음 아티클 추천
사용 가능한 목록에서 챗봇 응답 선택
6. 클러스터링(Cluster)
클러스터링은 텍스트 임베딩을 활용하는 또 다른 사용 사례 카테고리입니다. 이는 문서 그룹을 분석하여 해당 문서들이 어떻게 구성되고 서로 어떻게 연관되어 있는지 파악하는 것을 목표로 합니다.
이전 사용 사례에서는 문서 집합이 서로 얼마나 유사하거나 다른지 파악하기 위해 플롯에 문서들을 시각화했습니다. 클러스터링도 동일한 원리를 사용하지만, 여기에 문서들을 그룹으로 분류하는 단계를 추가합니다. 이는
k-means 클러스터링
과 같은 클러스터링 알고리즘을 통해 수행할 수 있으며, 클러스터 수를 지정하면 알고리즘이 각 데이터 조각에 해당하는 적절한 클러스터를 반환합니다.
이 Python
노트북은
Embed 엔드포인트를 활용하여, 3,000개의 "Ask HN"(Hacker News) 게시물을 어떻게 분석하는지 자세히 설명합니다. 먼저 각 게시물의 텍스트 임베딩을 생성합니다. 그 다음, 각 그룹을 대표하는 키워드를 보완하여 게시물 주제나 테마별로 더 작은 그룹으로 클러스터링합니다.
마지막으로, 아래 이미지에 표시된 그래프에서 각 색상이 하나의 주제 클러스터를 나타내도록 이 게시물들을 시각화합니다. 아래에서는 인생, 커리어, 코딩, 스타트업, 컴퓨터 과학과 같은 몇 가지 주요 주제가 나타나는 것을 확인할 수 있습니다.
상위 3,000개 Ask HN 게시물의 8개 클러스터. 각 키워드 세트는 특정 주제를 나타냄
이 기술은 다음과 같은 다양한 작업에 적용될 수 있습니다:
고객 피드백 및 요청 사항을 주제별로 정리
제품 설명을 기반으로 제품을 카테고리별로 세분화
ESG 보고서 및 뉴스를 주제별로 분류
방대한 양의 기업 문서 정리
설문 조사 응답 분석에서 새롭게 등장하는 주제 발견
7. 분류(Classify)
마지막으로 텍스트 분류 카테고리가 있습니다. 이는 오늘날 NLP의 가장 폭넓게 적용 가능한 활용 사례 중 하나이기 때문입니다. 클러스터링과 유사하지만 약간의 차이가 있습니다.
클러스터링은 "비지도 학습" 알고리즘으로 불립니다. 이는 클러스터가 무엇인지 미리 알지 못하기 때문입니다. 클러스터의 개수(어떤 숫자든 선택 가능)를 지정하면, 알고리즘이 해당 개수에 따라 제공된 문서들을 그룹화합니다.
반면, 분류는 "지도 학습" 알고리즘입니다. 이번에는 클러스터, 더 정확하게는
클래스(classes)
가 무엇인지 미리 알고 있기 때문입니다.
예를 들어, 이커머스 고객 문의 목록이 있고, 이를 적절한 담당 부서로 배정하기 위해 각 문의를 배송, 반품, 추적의 세 가지 클래스 중 하나로 분류하고 싶다고 가정해 보겠습니다. 분류기가 작동하려면 먼저 "당일 배송이 가능한가요?"와 같은 텍스트 예시와 그 실제 클래스(예: 배송)를 충분히 학습시켜야 합니다.
이
노트북
은 텍스트를 긍정, 중립, 부정 중 하나로 분류하는 작업인 감정 분석 수행을 위해 Classify 엔드포인트를 사용하는 예시를 제공합니다.
텍스트 분류가 유용하게 활용될 수 있는 몇 가지 예시 분야는 다음과 같습니다:
온라인 플랫폼 내 유해 댓글에 대한 콘텐츠 모더레이션
챗봇의 의도 분류
소셜 미디어 활동 기반의 감정 분석
이커머스 상품 분류
고객 지원 티켓의 적절한 팀 배정
결론
이 예시들은 LLM 활용 가능성의 극히 일부일 뿐입니다. LLM을 사용하는 가능성은 오직 우리의 상상력에 의해서만 제한됩니다. 이제는 거대 기업들뿐만 아니라 모든 개발자와 팀이 간단한 API 호출을 통해 제공되는 최첨단 AI 기술을 활용해 가장 까다로운 NLP 과제들을 해결할 수 있는 흥미로운 시대입니다.
