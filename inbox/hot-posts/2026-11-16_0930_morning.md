# 🏆 エージェント間プロトコルに「発着口」ができた — Poppy v1.0 と Shopify 全加盟店対応

**一言要約**: MCP=agent↔tool、A2A=agent↔agent、UCP=決済、という4層スタックの最下層「エージェントが会社前に名乗る」規格が居なかった — Sierra が 2026-11-14 に Poppy v1.0 を公開し、Shopify 全加盟店が自動対応、Meta Muse が全サイトで Poppy ファイルを最初に読む構成が揃った。

## ▶ 一言要約
Poppy v1.0 — Shopify 全加盟店が Poppy ファイル自動公開、Meta Muse が訪問先毎回チェック、デザインパートナー 100+ 社突破、Mercury / Synchrony / Turkish Airlines が先行稼働。

## 詳細
- **スタック上の位置**: MCP は [[concepts/mcp]] でツール発見、[[concepts/a2a-agent-protocol]] でエージェント間通信、UCP で取引を標準化するが、「エージェントが店舗 API に到着し、誰の代理人かを証明し、何を許されているかを知る」ステップが空白だった。Poppy がそこを埋める。新ワイヤーフォーマットは作らず、MCP + OpenAPI + OAuth + UCP の合成で v1.0 を組んだ。
- **採用の非対称さ**: Shopify は 175+ カントリーの全加盟店で、既に UCP デフォルト対応を理由に Poppy ファイルを自動公開。商家側の実装はゼロ。対照的に Meta の Muse エージェントは訪問サイト全てで最初に Poppy を探す。**供給側と需要側の両方を一斉に動かした**のが本リリースの核心。
- **認可設計の要点**: OAuth で顧客管理グラント、エージェントベンダーでなく顧客がスコープを握る。Mercury の例では残高照会・分類・予算は自由、送金は既存承認ポリシーを必ず通す — Poppy は平行な認可経路を作らず、口座のポリシーを継承させる。[[concepts/agent-identity-and-reputation]] の「caller ID for agents」問題の実装。
- **commerce 拡張**: [[concepts/agentic-commerce]] の UCP 側と継ぎ手を分離 — UCP が商品発見/カート/チェックアウト、Poppy が自己紹介+権限確認+UCP Ask 経由の買い物エージェント↔店舗エージェント会話。ゲスト or 顧客アカウントでの購入、特定アクション前の顧客確認を必須化。
- **留保**: 標準は Sierra が執筆・寄付、パートナー数と稼働事例は Sierra 側の数字。[[entities/sierra]]。競合の Decagon 製 PACT (Personal Agent Consent & Trust Protocol, 2026-10-07) との住み分けは未決着。標準が収束するか分岐するかは 2026 年内にもう一回注目。

## 深掘り
v1.0 の主な差分は「段階的導入の明示」だった — 5 週間のドラフト→v1.0 サイクルで追加された機能拡張は、既存標準(MCP/OpenAPI/UCP/OAuth)の再利用洗練とこれ。企業が個人エージェントのトラフィックを「受け取る」だけでなく「統治」したい要求を正面から認めた設計で、Sierra 自身の "personal agents — opportunity or threat" フレーミングに対応する。比較対象として Web 側の同じ発着口問題に [[concepts/webmcp-protocol]] がある — こちらは Google(Chrome)+Microsoft(Edge) が W3C Web ML CG で推進中だが未だ Community Group draft / Chrome origin trial。先週 Vercel UI SDK が WebMCP ページを公開し、typed React component catalog がそのままエージェントのツール面になった。Poppy が「企業入口」、WebMCP が「ページ入口」で、2026Q4 はエージェントの対話面が規格化される四半期になりつつある ([[concepts/death-of-browser]]、[[concepts/agentic-web]] 参照)。
