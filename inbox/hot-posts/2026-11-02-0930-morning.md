🖥️ Computer Useの瓶颈は「目」だった — Vercel Labs agent-desktopがピクセルを捨てる

**▶ 一言要約**: OSアクセシビリティツリーの安定refで操作するRust製computer useツール — スクリーンショット座標クリックを全排除、headless並行动作。

## 何が起きた

2026-10-31、[[entities/vercel-labs]] が **agent-desktop** を公開（「agent-browser, for your whole computer」）。開発はVercel Labsに加入したばかりの @mdlahfir、[[entities/chris-tate]] が拡散。

- Rust製CLI+Cライブラリ、macOS/Windows/Linux対応、`npm install -g agent-desktop` で入り x64/ARM64 ネイティブバイナリ同梱
- `snapshot` → 全操作可能要素に `ref` を振ったJSONを返す → agentはrefをクリック → 再snapshotで検証。観測ループはagent側のharnessに残る
- 操作はOSアクセシビリティAPI経由。**ポインタもフォーカスも奪わない headless がデフォルト**（物理入力は `--headed`）
- **複数agentが同一デスクトップを各々独自カーソルで並列使用**可能

## ピクセル方式との構造的差

従来の computer use（[[entities/openai-cua]]、[[concepts/gemini-computer-use]]）は screenshot→vision model→座標クリックの脆いループ。agent-desktop の設計は失敗モードを型で潰す:

| 失敗モード | 従来(ピクセル) | agent-desktop |
|---|---|---|
| UI変化後の誤発火 | 旧座標を信用しがち | `STALE_REF` / `AMBIGUOUS_TARGET` を返して再snapshot必須 |
| refの別ウィンドウ混線 | なし(座標に窓概念なし) | `AMBIGUOUS_TARGET` + `--window-id` 指定 |
| 削除行が同一IDの生存行に化ける | 検知不能 | macOSのprivate command hostがnative accessibility objectを保持して防止 |
| 検証 | 目視/ビジョン頼み | observe→act→observe の強制サイクル |

## なぜ効くか

- OSWorld の人間 baseline 72.4% / SOTA 83.6%（[[concepts/ai-benchmarks/osworld]]、[[concepts/computer-use]] の表）で頭打ちの要因はモデル知能でなく**観測の信頼性**。visionモデルの座標推定は確率的だが、accessibility tree の ref は決定的 — リトライ可能になる
- 「ツール側が観測の正しさを保証する」方向は [[concepts/harness-engineering/agent-ergonomics]] の延長線。[[entities/vercel-labs]] の他作（Zero のcapability-based I/O、fx、agent-browser、[[concepts/scriptc-typescript-native-compiler]]）と同じ agent-first design 系統
- 裏側: 2026-10のOSWorld系実験では Opus 4.7 のツール呼び出しの5%が「渡されていない幻影ツール」へのアクセスだった（[[concepts/computer-use]]）。観測を外部化し CLI envelope に固定するのは、この訓練済み先験に依存しない設計

## 注意書きと懸念

README は snapshot・clipboard・screenshot・debug artifact に機密デスクトップ内容が載りうると明記、公開ログ/アップロード禁止を要求。JEV helper（画面説明をモデルプロバイダへ送る）は native CLI から意図的に分離。アクセス可能性ツリーが信頼できる観測かという問いは [[events/trustfall-symlink-rce-2026]] のセキュリティ論点と接続する。[[concepts/web-accessibility]] のとおり、アプリ側の a11y 実装品質がツール精度の天井になる点も残る。
