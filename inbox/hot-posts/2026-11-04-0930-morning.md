# 🔬 Weight-Space Programming の「超human」主張、Goedeckeが24時間で反証 — 3行Pythonの heatmap vs 0.016% weight edit

**一言要約**: MIT CSAIL の「LLM が重みをネイティブに読み書き」論文 (HN 2,751pts) に対し、Sean Goedecke が「3行の numpy で同じ heatmap が出る。Qwen 修正も abliteration プレイブックそのもの」と24時間以内に反証した。

**詳細**:
- 論文側 ([[concepts/weight-space-programming]]): GPT-6 Astra がツールなし・勾配なしで — 17,253個の生重みだけから学習ゲームを Breakout 99%置信度で当て、Qwen3.5-0.8B の重み **0.016%** を直接編集して MATH-500 を **7.9%→48.1%**、IFEval 3倍。HN https://news.ycombinator.com/item?id=50341174
- 反証側 (seangoedecke.com、raw アーティクル 2026-11-03 取得): 「入力チャネルはラベル付き (agent / moving objects) で 8x8 グリッドに対応する。重みノルムを再整形するだけでどこのグリッドを見ていますかが出る」— Python 3行 (`np.linalg.norm(W1.reshape(...))`) の heatmap を自分で書いてみせ、パズル的な識別は人間でも可能と主張
- Qwen 修正の中身: 元々は「数学ができない」のではなく **32k tokens 超でループする**という特定障害。Astra はループする/しない推論テキストを4組書き、差分に寄与する重みを削るという手法を使った — Goedecke 曰く「これは [[concepts/abliteration]] / Heretic のプレイブックそのもの」で、有能な人間研究者が普通にやる手順
- Goedecke の類比: 「LLM がマシンコードを出すのと同じで、バイナリをいじる最善手はソースを書いて再コンパイルすること。重み更新の最善手も通常の学習」。LLM が AI research を助けるなら weight 手術ではなく **training の改善**経由
- 未決着点: 全実証は ≤0.8B の手作業で検証可能な規模に限定。frontier 規模に伸びるかは未検証。labs が RSI 用に明示学習させた能力か創発か (HN 最頻問) も不明

| 論点 | MIT CSAIL 論文 | Goedecke 反論 |
|---|---|---|
| ゲーム識別 | Astra が生重みから 99% | ラベル付き入力+3行 Python で人間でも可 |
| Qwen 数学改善 | 0.016% 編集で 6.1倍 | 32k token ループ障害の除去。 abliteration 相当 |
| 含意 | 「Adam/Muon の次は LLM による重み最適化」= RSI 経路再オープン | 「コンパイル済みバイナリの編集と同じ離れ業。学習を置換しない」 |

**深掘り**: この対立の裁定基準は「人間が同じ情報を得るのに何ツール/何ステップ必要か」の1点に集約される。重み編集の能力そのものは [[concepts/rome-weight-tampering-attacks]] (GPU メモリ上の rank-one 書き換え) や [[concepts/agentic-backdoors-via-pretraining-poisoning]] (事前学習データ汚染だけで RCE バックドア) で既に攻撃側が実証済み — Goedecke の「新能力ではない」は攻撃文脈では数年前から成立していた命題であり、論文の新しさは「防御/改善側で same-in-one-shot で成功した」点に寄せるのが正確。HN で yodon が指摘した通り、重み読解能力はバックドア検出と植入の両刃になる。
