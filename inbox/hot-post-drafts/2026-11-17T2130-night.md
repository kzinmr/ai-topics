## 🛰 エージェント時代、OSも信頼境界も疑え — 2026年11月の3本

**▶ 一言要約**: 11月15–17日の48時間で「エージェントを動かす台」を巡る一次資料3本がHNに計1107ポイント集まり、論点は性能から信頼境界へ移行している。

### 1. Windowsは「どのエージェントを使っているか」を測っている

- リバースエンジニア Xusheng Li の調査で、Windows 11 の `MissionControlAggregator.dll` に `copilot.exe` / `claude.exe` / `codex.exe` / `agy.exe`(CLI枠4つ) と `cursor.exe` / `antigravity.exe` ほか(デスクトップ枠5つ)の名前照合が確認された。
- 判定は feature flag **`CLICodingAgentUsage` (feature ID 62580080)** の背後にあり、ETW 経由で既定ONの "optional" 診断データとして送信される。集まるのはファイル内容やプロンプトではなく**ツール使用ビット**。
- HN 619ポイント / 472コメントの中心論点は「新しいプライバシー階級」ではなく「プラットフォーム固有の信頼毀損」— macOS/Linuxに一次パーティ製のエージェント国勢調査は存在しない、という比較。
- 皮肉は調査手段そのもの: 未公開機能を漁るのにAIエージェントが使われている。AIが解析コストを落とした対象はPHP2Shellの10年物のバグだけではない。
- 出典: [[raw/articles/2026-11-16_xusheng_windows-coding-agent-telemetry]] / <https://news.ycombinator.com/item?id=50524736>

### 2.  credential を渡さない — 「租借」という第三の道

- antonio (pico.sh) の **lend**: 使い捨てVMで動かすClaude Code/Codexに、秘密をコピーせず**socket転送で能力だけを借りさせる**。エージェント側はトークンも鍵も読まない ("secrets the agent never sees")。
- 設計要素は5つ — socket転送 / SSH再接続を跨ぐ安定socket / SSH鍵のアウトオブバンド保持 / 時間有界な**lease** / 操作監査。承認はスマホ側の `Ovis` プッシュでさばく。
- 位置づけは [[concepts/capability-based-security]] の系譜で、[[concepts/agent-trust-boundary-violations]] が列挙した credential-resident 型の事故を構造的に潰す。ただしランタイム隔離(sandbox)が「エージェントが自分のホストで触れるもの」を縛るのに対し、leasingは「オペレーターとして外部で何ができるか」を縛る — 直交する2枚の防御だ。
- 未解決は2点: 承認疲労(lease数が自律性と衝突)と、broker自体の特権集中。lendは単一開発者の単一記事なので confidence: medium。
- 出典: [[raw/articles/2026-11-17_antonio-cx_running-agents-without-credentials]] / <https://news.ycombinator.com/item?id=50526152>

### 3. 壊れているのはAI生成コードではなく「製造システム」

- Jimmy Breck-McKye の主張: 2026年の障害連鎖(Microsoft 2日間の世界規模障害、FAA全米発着禁止、PHP2Shell、eMudhra証明書、Shai Hulud NPM攻撃)は不運の連続ではなく**構造的状態**。AIは加速器であり症状であって、根本原因は「誰もシステム全体を頭の中に持てない」こと。
- PHP2Shellの核心は、runtimeに**10年以上**隠れていたメモリ管理バグ。Wizは「人間の攻撃者を大きく超える技量をAIが見つけた」と宣伝した。同じ週にWindows telemetryが見つかったのも、検出コストの崩落という一点で説明がつく。
- 反論も記録しておく: HN 230コメント側には「pre-2016のソフトウェア equally brittle であり、手作りの時代を美化している」という突き返しが残る。この記事は frontmatter 自身が `opinion` を公言しており、Microsoft の原因究明は非公開のままだ。confidence: medium。
- 出典: [[raw/articles/2026-11-16_breck-mckye_software-breaking-down-systemically]] / <https://news.ycombinator.com/item?id=50520866>

### 4. 反論 — 「性能の話はどこへ行った」

3本は性能・コスト・評価を一度も論じていない。エージェントの比較軸は [[concepts/agent-selected-hardware]] の「hackability」も含め、**台を誰が信頼できるか**に移っている。

| 層 | 失われた前提 | 2026年11月の一次資料 | 残った防御 |
|---|---|---|---|
| OS | 既定ONの診断は中立 | [[concepts/windows-coding-agent-telemetry]] (619p) | 手動で診断データを切る |
| 資格証明 | 秘密を渡さない限り安全 | [[concepts/agent-credential-leasing]] (116p) | lease + socket転送 |
| 供給網 | 依存関係は誰かが見ている | [[concepts/systemic-software-breakdown]] (372p) | 監視も修復も自動化で追いつけない |

この層ごとに一次資料が1本ずつ揃ったのは偶然ではない。評価・コストの話は11/16の [[concepts/qwen-4-max]] (594p) や [[concepts/dram-price-fixing-lawsuit-2026]] (181p) が既に担っており、信頼境界の話は別回線として立ち上がった。夜間の本稿は後者だけを拾う。

### 今夜の問い

自分のエージェントが動いているVMに、秘密は resident か、lease か。Windows機で開発しているなら、`CLICodingAgentUsage` の診断データを一度確認する価値がある。
