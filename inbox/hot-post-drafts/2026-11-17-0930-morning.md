**Anthropic Dreaming — session log を"睡眠"で再プレイして記憶スコア 3.7 倍**

**一言要約**: dreaming セッションを 2→128 回に増やすと graded-criteria スコアは 13%→48%。Anthropic がエージェント記憶の構成要素を公式分解。

**詳細**:
- 定義: 「エージェント記憶」= セッション間に保持される経験知識。重み変更・in-context learning・compaction は明示的に除外 ([[concepts/components-of-agent-memory]])
- 3 構成要素: (1) memory notes — 重要なイベントのタグ付け (2) dreaming — session log の offline 再プレイによる修正/新規表象構築/昇格 (3) wiki representations — Claude 自身による page 集
- 由来: Letta/UC Berkeley の [[concepts/sleep-time-compute]] を Anthropic が Claude 本番記憶に適用した first-party 版
- アナロジー: 海馬がオンラインで経験を capture し、睡眠中に新皮質へ統合 — agent では log/transcript を dreaming が replay する

**ベンチマーク実測** (出典: [[concepts/components-of-agent-memory]] frontmatter の raw article `anthropic.com--the-components-of-agent-memory-anthropic--90b9a347.md`):

| 実験 | 数値 | 教訓 |
|---|---|---|
| Wiki scaling (Stainless corpus, 350k files / 420M tokens) | dreaming 2→128 sessions で 13%→48%、wiki+search 61% vs search 単体 53%、~20k tokens/question 節約 | 計算量追加で記憶品質は対数的でなく線形に伸びる |
| CL-Bench 1.0 learning loop | Opus 5 が初 closed loop、Sonnet 4.6 は未検証理論のみ | ループ閉環は世代依存、Opus 5.5/Sonnet 5.5 も同水準 |
| Salience judgment (Pokémon Red) | Sonnet 3.7: 413 files/225 folders/1 badge → Fable 5: 9 files/4 badges | 画面読取状態を保存するな、戦略・計画・検証済み規則のみ保存 |
| Harvey LAB merger docs | cross-doc judgment 87% (wiki) vs 73% (search)、single-doc は差なし | 単一 doc 検索に wiki は不要。Borges "On Exactitude in Science" 失敗モード (wiki が corpus より肥大) も観察 |
| Goal-directed contract-terms | 共通テーブル要約 72% → reflection loop で build instructions 書き換え (per-contract page, verbatim quote, 1 agent/page) で **100%** | 「何のために記憶か」の steering が「どう書くか」の固定規則に勝つ |

**Steering の発見**: 「record only failures」という固定規則は Opus 5/4.7 の記憶ブーストをほぼ破壊。代わりに目的 (what memory is for) を提示する方が有効。Sonnet 4.6 に memory 読取 + 理論検証を促すだけで CL-Bench ほぼ倍増。

**Mt. Moon 修正例**: 誤った PokéCenter 位置 note が 3 回 ledge ループ失敗を誘発 → dreaming が transcript を replay して誤り検出し note 書き換え → Cerulean City 到達。ground truth である transcript を基準に memory を修正する具体機構。

**Anthropic 自身の open question** (3 点):
1. 書き込みタイミング — in-session capture は即時利用可だが attention を奪う、dreaming は background だが即時アクセス不可
2. 鮮度保持 — 連続検証は現実的でなく、変わりそうな情報に dreaming を集中させるか access frequency で頻度を調整
3. transcript search vs 維持された表象 — 併用は有効だが、表象側には誤り・幻覚蓄積を防ぐ計算量が必要
