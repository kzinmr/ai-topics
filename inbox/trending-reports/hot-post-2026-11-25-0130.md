# 深夜スロット: 「エージェントが人間を跨いだ」3例 — 8088・FPGA・9年落ちタブレット

**▶ 一言要約**: 2026年11月、著者が専門知識を一切持たない3つの異種ハードウェア(4.77MHz 8088、AWS F2 FPGA、Galaxy Tab S3)でエージェントが動作システムを完成。共通変数はエージェントの分野横断流暢性(Verilog / kernel C / Turbo C)だけで、人間の仕事は「正しさの契約と反復ループの定義」に縮退した。

## 詳細 — 数えるほどしか無い本当の制約

- **8088 は TLS を処理できない**。だから TLS 終端だけ「ブリッジPC」(`tunnel/tunnel.py` + socat/stunnel)に逃がし、API キーを PC のディスクに一切触れさせない。エージェントの設計判断として正しい分離。
- **ツールは18個**。`peek`/`poke`/`port`(メモリ・I/O直接アクセス)、`run` で Turbo C に ~450K フリーを渡し、タイマ割込みで CGA スクリーンショットを 8088 自身が PNG にエンコードして Claude に返す。メモリ/スキルは `C:\MEMORY` の平文コンテキスト — [[concepts/agent-skills]] と同一パターン。
- **Safe mode が既定 ON**。全 file/memory/port write に `Allow ...? (y/n)`。8088 上のエージェントですら権限要求を省かない。
- **FPGA 側で残った本当の壁はルータ精度**。MoE ルータは FP32 固定 — 精度を落とすと expert selection が変わる。高速化の内訳は burst attention、GCC-sort タイブレーク付き並列 MoE ルータ、head loader dual-bank read(+17.3%)、soak test で 231.25MHz に障害を見つけた後の 225/425MHz へのクロック刻み。
- **検証は論文レベルの梯子を維持**: ブロック別 cocotb 単体テスト → 実チェックポイントとの1層 co-simulation → 24層デコードの複数トークン比較。sim・timing signoff・ボード実測を互いに代用しないと明言。ここが「ノリで動く FPGA」との決定的な差。
- **プロンプトengineering の効率は低かった**: 「you're a superintelligent model, time to be more creative」が大半。4,741文字の外部知見を貼ると70秒で10採用/5棄却に分類したが、速度曲線は自律探索より動かず。Astra と Opus 5 はこの作業では互換。

## 深掘り — 「専門知識の壁」が人間の側へ移った

3案件の著者は標的ドメインの実務経験がほぼゼロ: FPGA 側著者は Verilog を書いたことが無く、10年 C++ も書いていない。ClawDOS のリポジトリは 100% エージェント作。なのに全部動くものが落ちた。

- 反証側に [[concepts/ai-engineering-dekilling]] がある — 分野横断流暢性は、正しさの契約を定義するのに必要な理解そのものを侵食しうる。
- 供給側の鏡像として [[concepts/code-review-bottleneck]]。Jellyfish の 700社テレメトリは企業側アウトプットをシニア人間のレビューが頭打ちにすると報告。この3例はレビュー関門が存在しないホビー/研究レジストリでだけ成立する。
- 「エージェントが蓄積を食う」ロジックは Jayden Milne の[[concepts/modest-success-software-boom|modest-success boom]] と接続する: Tab S3 の 2018年由来 freedreno バグのような放置 backlog が、平均品質生成の複利で片付いていく論。
- 経済数値($10K / 300万行 / 3000万行)は自己申告・単一ラン・独立再現無し。Wiki の confidence は artifact(スクショ、ベンチ表、MR)に high、経済主張に medium。

## このスロット向けの読み方

見世物としてのレトロエージェントは毎年出る。今回違うのは**収束** — 独立した3著者、無関係な3ドメイン、同一ワークフロー(エージェントが探索、人間が正しさを固定)、各自が「著者には無かったドメインスキルをエージェントが越えた」と報告している点。[[concepts/scaffold-vs-rl-debate]] の用語で言えば、3例とも scaffold(ツール・検証ループ・正しい反復の定義)が能力の瓶颈であり、重み側の RL はまだ表れていない。
