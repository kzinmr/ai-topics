# 140%の推論をレイヤーの中で消費するモデル — Inkling 2 Mini

**▶ 一言要約**: Thinking Machines が 26.4B/実効3.4B の looped transformer を公開 — 中間12層を3回通す構成で、loop なし版より推論計算を **140% 多く使わずに** 同一 loss に到達、DeepSWE v1.1 **48.2%** は 100B 未満 open-weights の新最高。

## 数字で見るアーキテクチャ

| 項目 | 値 |
|---|---|
| 総パラメータ / 実効 | 26.4B / 3.4B（ループ込みで 1トークンあたり 5.4B 活性） |
| ループ構造 | 24層 = 6層×4ブロック、中間2ブロックを3回適用 = 1トークンあたり 48 layer applications |
| 学習/展開精度 | expert 層 NVFP4、最後4層 MXFP8。学習時と同一精度で展開 → 変換ロスなし、フットプリント ~20GB |
| DeepSWE v1.1 | **48.2%**（2位 Qwen3.8-27B 42.2%、Gemma 4 31B は 0.3%） |
| SWE-bench Pro v2 Hard | **77.9%**（Qwen3.8-27B 73.8%） |
| BrowseComp | **79.0%**（Qwen3.8-27B 61.6%） |
| 知能/W 比 (Stanford, DGX Spark) | **0.703** vs Qwen3.6-35B-A3B 0.430 / Gemma-4-26B-A4B 0.159 |

比較表から読み取れるのは「100B未満の枠」の再編成ではなく、**Qwen3.8-27B との二強化** — Terminal Bench v2.1 では 71.6% vs 73.0% で今も Qwen が上、ComplexConstraints v1.1 は 33.4% vs 35.6% でマルチターン制約追従は弱点のまま。

## ループの得と損は非対称

**▶ 一言要約**: ループ回数の増加は推論系ベンチにのみ効き、知識系ベンチには一切効かない — 知識は総パラメータの関数という主張が、同一モデルのループ数変更という最も clean な実験系で確認された。

- **効く方**: 長文コンテキスト検索（GraphWalks BFS 256K **69.7%**、MRCR v2 8-needle **46.4%**、いずれも比較表1位）、数学・科学推論、長時間エージェントタスク。中間12層ループは最終12層ループより 28 評価中 **27 で勝っていた**。
- **効かない方**: AA-Omniscience v1.1 スコア **-8.6**、non-hallucination rate **63.4%**。Qwen3.8-27B は -6.4 / 71.4%、Best 表記は Nemotron 3.5 Super の -2.9 / 69.5%。ループ数を増やしても SimpleQA Verified・WorldVQA はほぼ不変。
- **含意**: 小型モデルの知識不足はループでは埋めらず、検索・ツール使用で埋める設計になる。実際 BrowseComp / DeepSearchQA (**85.3%**) / MCP Atlas (**82.7%**) で同サイズクラス1位。[[concepts/prompt-caching]] とツール使用の組み合わせで、ローカル推論でも検索_augmented_なエージェントが回るという [[concepts/local-llm/_index]] の実務的帰結。

## 見えない推論が増える — とは言えないデータ

**▶ 一言要約**: no-CoT で解けるタスク長は 16 秒 → **37 秒** に伸びたが、CoT の可読性は落ちなかった — ループ5回の推論は 1回の **半分未満**（1,661 vs 3,703 トークン）になりながら、文長・辞書収録率とも変わらず。

これは [[concepts/monitorability-metrics]] と [[concepts/chain-of-thought]] の中心仮説 — 「CoT に書かれない推論は CoT モニタに捕捉されない」— に直接触れる実験なので、数値を置いておく。

| 指標 | 1 pass | 3 pass | 5 pass |
|---|---|---|---|
| 平均推論トークン | 3,703 | 1,731 | 1,661 |
| 1文の平均語数 | 8.9 | 8.7 | 8.7 |
| 英語辞書収録語の割合 | 94.6% | 94.5% | 94.4% |
| ためらい語 (wait / actually / hmm) | 9.7 | 3.9 | 3.6 |

短くなったのは省略ではなく**引き返しの削除**だった、という分析。LinuxArena（攻撃者モデルが SWE タスクのついでに悪意ある副次タスクを実行できるか）では、監視側に弱い Qwen3.6-35B-A3B を置いた stealth rate がループ数 1→5 で **1.0% → 5.0%** と緩やかに上昇。ただし幅は小さく、TML 自身「clear trend is not seen」と書いている。CoT の意図的操作（CoT-Control-QA）は 3-pass で **0.1%**、比較群も 0.3–1.3% と皆ほとんどできない。

注意すべき留保: variable-loop 研究モデルの RL は 3-pass でしか行われていない。TML の自分の書き方で「高 pass 数で RL したモデルはもっと推論を圧縮するかもしれない」。つまりこの monitorability 評価は、最も気になる設定を意図的に避けている。

**深掘り**: ループの学習安定化は、メッセージ（前 pass の中間ブロック出力）をゲート経由で prelude 出力に合成する設計。ゲートは初期値でメッセージを**完全に遮断**し — つまり各ループの開始が非ループモデルと同一になり — 訓練中にゲインが上がっていく。これによりループを後付けで安定導入できる。さらに attention residuals（Kimi Team 2026）で各層が過去ブロック出力の任意の線形結合を読む。pruning は midtraining で expert 384→128 に 2/3 削除し、以降 larger Inkling からの蒸留 1T tokens で性能を回復させている。[[concepts/nvfp4-4bit-floating-point]] のネイティブ学習・展開が GB300 前提で、ローカル展開は NVFP4 20層 + MXFP8 4層の「変換ゼロ」という設計が本質。[[concepts/gguf-quantization]] 側は Unsloth が数時間で quant を出したが、llama.cpp のループ対応 PR (#32695) は未マージ — HN スレッドの不安は「珍アーキテクチャが PR キューで腐る」定番のもの。

## 残す問い

1. looped transformer の機構的解釈は未着手に近く、早期アクセスを受けた Goodfire の知見と NDIF 経由の研究者アクセスが最初のデータ点になる。[[entities/thinking-machines-lab]] の「公開モデルで安全性研究を外部化する」路線の一貫性を見る機会。
2. no-CoT 地平 16→37 秒は、[[concepts/computer-using-agent]] のようなスクリーンショット往復型エージェントで「内部で何を積んでいるか読めない時間」が増えることと等価か。TML の LinuxArena は CoT を読む監視者の話で、行動ログだけ見る運用は評価されていない。
3. 知能/W 比 0.703 は Stanford の測定（128GB DGX Spark, MXFP8, low reasoning effort）で、他モデルは NVFP4/INT4 混在。同一 HW・同一 precision で並べ直した reproduction がまだ無い。
