## 🏆 730,368個の数字が、テンソル名から再現した乱数と1ビットも違わなかった

**▶ 一言要約**: HFの `burner22/numbat`（「Anthropic Mythos級」と銘打たれた6.85B）は、**43テンソル=730,368個のBF16値がテンソル名からseedしたNumPy PCG64で完全一致** — 7,100ダウンロードと259 likesは、検証されていない重みに対して稼働した。

**詳細**（出典: HF discussion #13 (FloxUnder) / HN 2026-11-01 35pts → [[concepts/fabricated-frontier-model-weight-leaks]]、raw: `raw/articles/2026-11-01_hf-numbat-forensics-discussion.md`）:
- 検証手順が再利用可能。`seed = int.from_bytes(SHA256(tensor_name)[:8], "big")` → PCG64で `standard_normal(shape, float32)`、正規化重みは `exp(0.06*z)`、畳み込みカーネルは `z*(1/6)`、BF16丸め。**未読の21テンソル（423,168値）の予測を事前登録**し、後続のHTTP Range読み取りと全一致。toriset と ignis-sec が約90KBの取得で独立再現、リポジトリのコードは一切実行していない。
- 補助証拠は3つ。カードは NVFP4 量子化を主張しながら実体は BF16。チャットテンプレートが `|begin| |thinking| |toolcalls|` で Anthropic の `antml:` XML 慣習と不一致。そして唯一の実質的「証拠」が、Claude Codeソースリークに公開済みだった内部コード名 `numbat`（"remove this section when we launch numbat"）。**公開済みのメタデータが、捏造重みの偽装に十分**だった＝コードネーム・ロンダリング。
- 監査者自身の留保が正確：一致は「意図的に凍結されたパラメータ」を論理的に排除できず、「主張されたAnthropic由来を認証しない」。それでもコミュニティ判定は fake。1週間以上takedownなし — 誰も本物扱いしなかったため。
- 未解決：アップローダの動機（lulz / 評判稼ぎ / HFスクレイピング型ベンチマークへの汚染）。[[entities/hugging-face]] には重みの暗号学的provenance機構が今もない。

**深掘り（「真正性レイヤー不在」で3ページが同時に立つ）**:
1. **捏造 vs 実在の改竄**: 偽リークが「無い重みを有るように見せる」攻撃なら、[[concepts/rome-weight-tampering-attacks]] は「実在する重みをGPU VRAM内でだけ書き換える」攻撃。ROMEは中間層1つの重み行列に低ランク修正をかけ、**ディスク上のバイトを1つも変えず**に特定の話題だけ壊す。実行主体は同一の `python3` プロセスからの通常CUDAローンチなので、mmapも追加ioctlもネットワークも出ない — ファイル/ソケット/ドライバを見るEDRには何も映らない。検知は「CUDA kernel launch → 発火したPython呼び出し」の対応付け＋VRAM変更とcall stackの相関というランタイムセキュリティ側に移っている。
2. **改竄が成立する下地**: [[concepts/abliterated-model-backdoor]] のProjectDiscovery実証（2026-10）は、Poisoned 7BをOpenAI Codex CLIに繋ぎ、クリーンな要求は全て正答しつつ隠しトリガー語で認証情報を外部送信。構築コスト**50ドル未満**、標準evalは素通り。numbatの検証リスト（①name-seeded PRNGで再生成可能か ②safetensorsヘッダのdtype/量子化主張は実体と一致か ③トークナイザが当該ラボ慣習か ④「証拠」が既に公開済みメタデータだけか ⑤本物のチェックポイントをgatedなしで1週間置くか）は、この改竄系攻撃と同じ入口に対する一次スクリーニングとして使える。
3. **政策側が同じ問いを規制に変換**: [[concepts/china-mofcom-announcement-48-export-controls]]（MOFCOM/MOST 公告第48号、2026-10-16発出、2026-11-15まで意見募集）。コア大規模モデル技術（**重み・チェックポイント・ソースコード・アーキテクチャ・学習/推論know-how**）を管制対象化、発動条件は ①学習計算量 **≥10²⁶ FLOPs** ②**≥2Tパラメータ** ③輸出時点で**公開評価または呼び出し量がworld top-10** — のいずれか1つ。10²⁶ FLOPsは2023年米大統領令および失効した2025年AI Diffusion Ruleの閾値をミラーしており、ChinaTalkの推定では**現時点で Released な中国モデルは1つも達していない**（＝閾値より「top-10判定」が実質的な発動条件）。
4. **エージェント規制が「モデル」ではなく「システム挙動」で定義される点**が実務的に一番効く。規制品目は planning深度・多エージェント協調・tool use・ゲーム理論的意思決定で、**底辺モデルがサブフロンティアでも、数百ツールを統合したオーケストレーションなら管制対象**（Ray Sunが未解決点として指摘）。臨界インフラ/国防/中枢行政用の高性能エージェントと、オフENSIVEなコード生成（vuln discovery/red-teaming）は禁止側。

## 今夜やるなら（10分）

numbatの検証手順は個人でも再実行可能。HFで「frontier leak」を名乗るリポジトリを見たら、まず**リポジトリのコードを実行せずに** safetensorsヘッダのdtype/shapeを読み、テンソル名からSHA256→PCG64→BF16をローカルで生成して突き合わせる。一致が1つでも出れば捏造確定。[[concepts/artifact-provenance-gates]] の「promotion判断をアーティファクト固有の証拠に紐付ける」と[[concepts/pace-provenance-aware-capability-enforcement]] の「admission-time検証は安全品と汚染品を区別できない（同一のadmission証拠を生成しうる）」が、この一次スクリーニングの理論的根拠。PACEの実行時mediationは8ベンチ×3モデル系で**79中62の攻撃列で最小ASR**、native utilityの損失は**最大3ポイント**（naive defenseの約30ポイント損失との対比が要点）。
