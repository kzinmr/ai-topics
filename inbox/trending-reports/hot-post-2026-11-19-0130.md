## 📊 frontier LLM の98.7%を「LLMを使わず」に叩き出す — PostHogが実運用で確定させた decision model の4パターン

**▶ 一言要約**: PostHog本番でセッション要約の98.7%がLLM呼び出しゼロで完了。閾値は「精度」ではなく「誤りの非対称コスト」で決める。

**詳細** (出典: Jina Yoon "Not everything needs an LLM", 2026-11-09, HN 160p / raw: `raw/articles/2026-11-09_posthog_not-everything-needs-an-llm.md`):

decision model ([[entities/typesafe-ai]] の Jev、[[entities/gemini-decision-1]]、GPT-6 Luna) は自由文ではなく **Noul(yes/no)/Choice/Score の型付き答え + calibrated probability** を返す。PostHogがそれを本番で使う初のプレイブックを公開した。4パターン:

| パターン | 実装 | 数字 |
|---|---|---|
| ① 高価なLLM呼び出しのゲート | PII scrubbing を「実在人名か」「連絡先/IDが見えるか」の2つの狭いyes/noに分解 → その後の Gemini 呼び出しを判定 | セッション要約の **98.7%がLLMスキップ**。2分割で誤フラグが単一質問の約1/10 |
| ② モデルルーティング | 「最初に正しく終わる最安モデル」を capability note 付き候補から Choice 質問で選ぶ | **閾値はモデルバージョン/プロバイダ間で移植不可** → project 別設定 + shadow mode 判定 → モデル非依存の社内AI gateway に着地 |
| ③ 前処理後の値切り判定 | 「条件に合う top-10 セッション」は無理。embeddings で事前絞り込み → 一致判定を1パス | decision-model 確率によるリランクで順位品質 **約+25%** (20 query) |
| ④ overqualified LLM / 決定論ルールの代替 | SQL チャートピッカーをハードコード規則 → SQL+先頭3行を読む decision model へ | 逆例: PR検索の5 noul 質問は **AUC 0.52(=コイントス)** |

- 閾値設計の核心: PII は **0.4**(誤検知より個人データ保存のほうが高い誤り)、Slack bot の不用意回答は **0.85**(誤検知=邪魔なのが最も高い誤り)。同じ模型・同じAPIで閾値が真逆になる。
- 3質問API (Noul/Choice/Score) は Jev・GPT-6 Luna・Gemini Decision 1 で共通 → プロバイダロックインがない。
- 対抗手段: PostHog は自作ハイブリッド **Jeeves**(迷ったときだけ考えてから決める)を unnamed-model のデフォルトに。長文脈は Jev 公式 64k/request・32k/question(オプトインで262k だが遅く精度低下)。
- 適用可能領域の境界線: 「正規表現には曖昧すぎるがLLMほど複雑でない」単一パス判定のみ。マルチステップの decision-model チェーンは技術的には可能だが運用価値ゼロ(1時間32セッション/12–38k tokens のJobがモデルサーバを数時間飽和)。
- 数値の扱い: 444.6× 安い/193.6× 速いは [[entities/typesafe-ai]] のベンダー申告を PostHog が引用した値。独立検証なし。

## 深掘り: なぜ「校正」が選定基準なのか

PostHogの閾値ルールは、[[concepts/calibrated-escalation]](Hightouch, 2026-11-04, HN 488p)の実証をエンジニアリング手順に落としたものだ。Hightouch の identity-resolution 監査データが示すのは、単体精度ではなく**校正品質**がカスケード設計の合否を決めるという一点:

| 構成 | 精度 | 1,000件あたりコスト |
|---|---|---|
| Claude Opus 5.5 単体 | 99.0% | $3.86 |
| Jev(60% cut)単体 | 95.7% | $0.05 |
| Jev → 低信頼帯のみ Opus 5.5 | **98.8%** | **$0.88** |

frontier 精度を 4倍以上安く出す。ただし Hightouch の数値は pseudopeople 合成データ上・自社観測ベースで、2026-11-07 時点の独立再現なし(両ページとも confidence: medium 扱い)。
PostHog の貢献は、そこから一段進んで **(a) 閾値を「誤りのコスト比」から逆算する運用、(b) shadow mode による閾値検証、(c) 判定モデルの長文脈は embeddings で肩代わりさせる** という、再構成可能な手順にしたこと。[[concepts/context-engineering/_index]] の「全部 frontier に投げる」デフォルトに対する現時点で最も実装済みの反論。
