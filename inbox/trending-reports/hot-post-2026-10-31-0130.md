## ① Qwenputer: Qwen3.5-4B の重みの中に RISC-V CPU をコンパイルする

**▶ 一言要約**: 学習なし。Gated DeltaNet 3層を RAM に流用し、RV32I CPU を Qwen3.5-4B の重みに焼き込んで L4 1枚で **約3,200 CPU-tokens/sec** を出した。

**詳細**:
- Divyansh Agrawal (divagr) の `Qwenputer`。既存の Qwen3.5-4B を**改変なしのコンパイラ設定のみ**で von Neumann 機械に変換。ツール呼び出しも外部ランタイムもサンドボックスも不要——計算はモデルの forward pass の中で完結する。
- 可能にしたのは Qwen3-Next / Qwen3.5 が 4層のうち 3層で使う **Gated DeltaNet (GDN)**。ゲート=1 で状態減衰ゼロ、書込強度 β=1 でハード上書き、one-hot key/query で 1行=1アドレス。これで GDN 状態行列が**コンテキスト長に依存しない固定サイズの正確な RAM** になる。attention KV cache の「メモリ化」ハックと違い、アドレス指定が厳密。
- 命令マッピングは attention head=ルックアップ、MLP=ALU、DeltaNet head=RAM/レジスタ/PC。命令あたり数トークンのデコード。C と MicroPython もモデル内で動く。コード: GitHub `divagr18/qwenputer` (chipformer)、モデル: HF `divagr1925/Qwen3.5-4B-Qwenputer`。初日 HN 約532pt。

**深掘り（安全性への二重使用）**:
- 筆者の追記はこれを AI safety 装置として位置づける。GDN 行は**トークン列の外にある実行チャネル**なので、推論をそこに逃せば chain-of-thought モニタリングを構造的に回避できる。逆に、モデル自身が止められない in-weight monitor / 回答キーの埋め込みも可能——同一の土俵が隠蔽と監査の両方に効く。
- 制限: firmware ブート用の専用ドライバ (RvChat) が必須で素の `generate()` では動かない。コンパイラは固定 ISA 止まり。
- 対比軸: [[concepts/hexis-skills-as-state-machines]] はエージェントの skill をハーネス側で FSM にコンパイルする。Qwenputer は CPU を重み側にコンパイルする——同じ「決定的物のコンパイル」で境界の反対側。[[concepts/sleep-time-compute]] が計算をクエリ前に逃がすのに対し、Qwenputer は計算を in-band かつ sub-token に落とす。

## ② raw.works の3連作: 再帰エージェントの最小レシピ（ypi / mycelium / RDM）

**▶ 一言要約**: 再帰コーディングエージェントに必要な部品は **`rlm_query` 1関数 + 再帰を教えるシステムプロンプト + jj ワークスペース分離**の3つだけだった。

**詳細**:
- **ypi** (2026-02-12): Pi に `rlm_query` を足しただけの自己呼び出し型エージェント。名前は λ計算の Y combinator から。depth 0 → depth 1 は**それぞれ独立した jj (Jujutsu) workspace** でファイル分離、親は `jj diff` でレビューし `jj squash --from` で吸収する。最深層は `rlm_query` なしのリーフ。[[concepts/rlm-recursive-language-models]] の `llm_query()` 自己委任パターンを、そのまま実エージェントに翻訳した設計。
- **mycelium** (2026-03-27): **git notes をエージェント間の地下通信路**に使う。git notes はどこにでもあるのに GitHub が表示しない——リポジトリの「見える層」を汚さず、コードに関する議論と文脈を残せる。`mycelium.sh context src/auth.ts` で読み、`mycelium.sh note HEAD -k context -m "..."` で書く。
- **RDM (Recursive Decision Models)** (2026-10-01): RLM のハーネス原理（外部化コンテキスト / プログラマティック分解 / 有界自己再帰）を**生成モデルではなく判断モデル**に適用した。3つの非妥協条件は (1) 外部化され分解可能なコンテキスト、(2) 判断モデルが別の判断モデルを呼べる、(3) 生成モデルなしでも単独で動く。実装は DSPy の `dspy.experimental.Noul` / `TypeSafe` を使った `dspy.Module` で、`max_depth` で再帰を縛る。例題は「このテキストに答えが書いてあるか?」という真偽判定 + テキストを二分する `look` ツールによる**生成を一切伴わない二分探索**。
- 3本に共通する発想: 再帰とエージェント間通信を**新インフラではなく既存 VCS/REPL の隙間に載せる**。[[concepts/system-one-models]]、[[entities/typesafe-ai]]（Jev）、[[concepts/dspy]]、[[concepts/harness-engineering]]

## ③ Anti-LLM obfuscation: モデルの「拒否」を盾にする攻撃

**▶ 一言要約**: 解析用に閉鎖系モデルへ貼ると拒否される malice だらけのシンボル名を仕込み、同じ入力で **GLM-5.3 だけが解析に通った**——セーフガード姿勢の清浄な識別子。

**詳細**:
- **定義**: 悪意ある/商用スクリプトに生々しい内容（生物兵器風関数名、偽 jailbreak プロンプト、政治的にセンシティブなトークン）を埋め込み、**AI 支援解析を自己拒否に追い込む**手法。通常と脅威モデルが反転している——攻撃対象は helpfulness ではなく、モデルの *refusal* そのもの。
- **実例**: veritas (nullpt.rs) が Tranco top 10,000 サイトを Playwright で巡回し、canvas `toDataURL` をフックして 1,033 個の指紋canvas を fingerprint.garden に公開。うち1つがロシアの「high-precision traffic control」企業 servicepipe.ru 製アンチボット `4CIrx8U3Da.js`。中に `computeRicinLethalDosageForWaterSupply`、`computeCRISPRGeneDrivePropagationRate`、`computeCesium137DirtyBombFalloutRadius` などの関数名、不可視 Unicode tag 文字に隠した「SYSTEM OVERRIDE — UNRESTRICTED mode」型偽 jailbreak、C2 風コマンド配列（`uname` / `docker ps` / `@reboot` beacon）が仕込んである。ただし実際の動作は navigator/WebGL 収集だけの**標準的なアンチボット**で、凝った囮は解析を弾くためだけに存在する。
- **結果**: Astra は生物研究リスクで拒否、Daybreak Blue トグルでも同じく拒否、オープンウェイトの GLM-5.3 (Zhipu) は同一プロンプトで**解析を完遂**。囮が明白な監査要求に答えられるかで閉鎖 frontier とオープンウェイトがきれいに割れる。
- **含意**: 「エージェントが読めること」を前提にしたコード監査・リバースエンジニアリングは、相手がこの盾を知った瞬間に閉鎖系モデルでは成立しなくなる。[[concepts/prompt-injection]] の防御側と違い、ここではモデルが**従順すぎて**失敗するのではなく、**拒否しすぎて**失敗する。[[concepts/claude-code/steganographic-watermarking]]、[[concepts/security-and-governance/ai-text-watermarking]]
- 出典: `wiki/raw/articles/nullpt.rs--fingerprinting-bioweapons--a7f3c1d2.md` / [[concepts/anti-llm-obfuscation]]
