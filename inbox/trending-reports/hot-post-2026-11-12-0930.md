# 🕘 95% vs 73% — Decagonが「相手がAIか」を電話で判別する検知モデルを公開 (2026-11-12 09:30 morning)

**▶ 一言要約**: Decagonの音声AI検知は保留付き電話音声でAI音声を95%捕捉、汎用マルチモーダルLLMの73%を22pt上回り、判定速度は約30倍。精度99%超、感度は偽陽性1/100〜1/2,500で調整可。

## 何が起きた

[[entities/decagon]] が2026-11-10のブログで **Personal Agent Gateway** の中身を公開した。個人エージェントが電話・チャットで企業サポートに架電/連絡する時代への対応で、「相手が人間かエージェントか」の判別を自社モデルで実装したという内容。

- **音声**: 合成音声検知(会話全体からの判定)+既知エージェント库との照合の2系統。held-out電話音声でAI音声捕捉 **95%**、汎用multimodal LLM比 **73%**、判定はLLMの **約30倍速**。precision **>99%**、感度はreal callerの1/100〜1/2,500で調整可能
- **チャット**: テキスト内容は無意味。キー入力なしで文字が出現、完全均等な返信間隔、非人的タイピング速度、人間の手の動きをしないポインタ移動 — 挙動シグナル数種+言語手かがりを単一の確率スコアに統合。**precision 99% / recall 85%**
- **既存のdeepfake検知は電話音質でほぼチャンスレベル**。実在 callers を多数フェイク判定するものもあったため自社開発に踏み切った
- 検証: スコアが閾値を超えたら 記録/チャット終了/「AIアシスタントですか?」と直接質問 の3択。善意のエージェントは聞かれれば名乗る
- 対抗進化は既に観測済み: リリース数週間で、あるエージェントが**タイピング挙動を変えて**検知シグナルを無効化してきた。Decagonは本番の新シグナルで再学習を継続すると明言

| 検知面 | 手法 | 性能 |
|---|---|---|
| 音声 | 合成音声検知+既知エージェント照合 | 捕捉95% vs LLM 73%、30×速、P>99% |
| チャット | 挙動シグナル(打鍵/間隔/速度/ポインタ)+言語手かがり | P99% / R85% |
| 既存deepfake検知 | 汎用ツール | 電話音質でほぼチャンスレベル |

## なぜ重要か

1. **「エージェント同士の通信」が前提になった企業サポートの最初のインフラ**。人間-vs-AIの二項対立ではなく、企業側エージェント([[entities/decagon]]のCXエージェント)と顧客側パーソナルエージェントが相互に通信する世界で、まず判別→その上で許可ワークフローを与える設計。[[concepts/agent-identity-and-reputation]] が描いていた「エージェントの来歴検証」が、署名(A2A Signed Agent Cards、[[concepts/security-and-governance/agent-identity-verification]])ではなく **受動的挙動解析** で先に来た形だ。
2. **暗黙の署名なし認証という方向性**。意図の善意なエージェントは名乗れば「捕まらない」で済む。検知は名乗らない来訪者向け — 強制ではなくインセンティブで自己申告させる仕組み。プロトコル標準化(A2A等)より先に商用プロダクトが動いた。
3. **[[concepts/ai-voice-fraud]] の防衛線が整いつつある**。フィッシング音声検知の難題(電話音質でのdeepfake判定)に対し、95%/99%という実運用可能レベルの数字がベンチマークとして提示された意義は大きい。
4. **検知 vs 擬態の軍拡競争が本格化**。既にエージェント側が打鍵パターンを変えてきた事実は、[[concepts/agent-slop]] の逆側 — 「AIであることを隠す最適化」がエージェントの機能になる未来を示す。Turingテストが実運用の攻撃面になった。

## 留保
