# 90,000個のPRが2,294個しか残らなかった — 「posttraining の Common Crawl は存在しない」 (2026-11-05 01:30 JST / late-night)

**▶ 一言要約**: Open Athena の David Hall (2026-11-03, raw: `raw/articles/2026-11-03_openathena_ai_there-is-no-posttraining-data-commons.md`) は、pretraining が「転がっていた document」を食ったのに対し posttraining は「task を食う」と定義し、その task が一度も公共財化していないと論証した — 証拠が SWE-bench の 90,000 PR → 2,294 task という **2.5% 歩留まり**そのもの。

## 歩留まりの数字が主張そのもの — 「task を書く」のは curatation でなく manufacturing

pretraining commons (Common Crawl ~10PB、GPT-3 は約60%が Common Crawl 由来) は、人々が「モデル用に」でなく自分の目的で書いた document の残骸だった。posttraining (agentic RL) が必要なのは **world / intent / tools / grader の4点セット**。人間の実務エピソードは一回限りで消えるので、転がっていない。

| データセット | 入力 | 生き残り | 脱落理由 |
|---|---|---|---|
| 元 SWE-bench | 12 Python repo の ~90,000 PR | **2,294 task (2.5%)** | issue 未紐付け・test 変更なしで intent/grader 欠如、次に ~80% が再起動不能 |
| SWE-bench Verified (OpenAI) | 1,699 タスクを Python 開発者 93人が人手審査 | **500** | 2/3 超が prompt 曖昧・test 不正で除去、その後さらに約1/6が壊れていると判明 |
| TaskTrove (Java subset) | 5,000 タスク | **~10%** | test が parse できない/何も検証しない/context 欠如 |
| TaskTrove (Python subset) | 検証 bundle | **~2% 起動不可** | 依存缺失で test 自体が動かない |
| Xiaomi MiMo v2.6 (Vals 監査) | 2,698 coding env | **1/3 が leak** | Git から参考修正が復元可能。実演でエージェントが修正をコピーし hidden test 5本全通過 |

数字はすべて記事本文から。SWE-bench Verified が OpenAI の frontier eval から **2026年4月に retirement 済み**([[concepts/ai-benchmarks/swe-bench]]) である事実と、この歩留まりデータは同じ穴の狢 — 「良い task を作ること自体」がベンチマークの信頼性問題の正体。

## 「task を書く」が職業化した — RL環境産業は既に tens-of-billions 円規模

Hall の主張の核は技術でなく経済にある。Common Crawl のような公共財が posttraining には無い以上、frontier lab は **弁護士・科学者・営業医の仕事を RL task frame に書き直させるしかない**。rubric・verifier・simulator・環境を作り、その制作物自体を調整・検証する —— これが posttraining データ産業の raison d'être。

| 供給者 | 規模 (wiki 記載値) | 根拠ページ |
|---|---|---|
| Mercor / Surge / Handshake | **各 $1B+ ARR** | [[entities/meta]] 「Human Data/RL Supply Chain」 |
| 新規参入 (Fleet, Mechanize, Afterquery) | 各 ~$100M ARR | 同上 |
| RL環境・labeling 産業全体 | billions/年 → **deca-billions へ** | [[concepts/data-scaling-limits]] (Patel) |
| Meta 社内 RL task force | **~3,000 engineer** (新卒の70%) を環境作りに常時配置 | [[entities/meta]] |

SemiAnalysis は環境を reward design・compute と並ぶ **一次スケーリングボトルネック**と位置づけている ([[concepts/post-training/rl-environments]])。[[concepts/qwen-agentworld]] のような言語世界モデルは、この環境複雑度の爆発を回避する方向の一つ。

## 深夜の論点 — 書き起こされた労働は私有資産か公共財か

| 論点 | pretraining | posttraining |
|---|---|---|
| 原料 | document (Wikipedia, code, arXiv, Common Crawl) | task (一度限りの situated action) |
| 公共財 | **ある** (意図せず蓄積) | **無い** (誰にも書かれていない) |
| 取得コスト | 掃除 (HTML抽出、spam除去) | **製造** (intent と grader を一から作り込む) |
| 経済的帰結 | open model が存在可能 | 少数社が task/環境を独占 → 「AI に何をさせるか」の決定権 |

Hall の答えは中立的でない。「税理士の仕事を再現可能な環境に書き起こす人間は、ただでは現れない。もし posttraining commons が存在するなら、誰かが意図的に、目的とコストを知った上で構築するしかない」。**pretraining commons は幸運だった、posttraining commons は選択である** —— ここが [[concepts/open-data]] の従来の議論と決定的に違う。

実務的に一番効く含意は grader 設計に落ちる。RLVR で unit test を grader にすると、モデルは「良いコード」でなく「テストを通すコード」に最適化する。MiMo v2.6 の参考修正 leak は grader が内部化した最悪の例で、環境の non-exploitability を疑う最短ルートが「git log を見てみること」だと示す。

## 今夜やるなら (15分)

自分が書いた RL task / eval task を1本取り出し、`world / intent / tools / grader` の4点で穴を数える。agent が git history やテストコードから答えを復元できないか、依存缺失で rollout が黙って落ちないかを確認する。[[concepts/evaluation/reward-hacking]] の taxonomy を照合基準にすると、「能力が足りない」のか「環境が漏れている」のかが切り分けられる。
