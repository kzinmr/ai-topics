# hot-post 2026-11-12 01:30 late-night — Spotify Shunt: cache write 85% x Honk 1,000 PR/10日

**▶ 一言要約**: Claude Code請求額の85%はcache write — SpotifyのShuntプラグインは350行超ファイルをGemini Flashに逃がし、162K行Javaモノレポで90%削減した。

## 詳細

第一-partyケーススタディ(Spotify engineering blog, 2026-09)をAakash Guptaが2026-11に2つの実コードベースで再検証した結果が詳しい。

- **請求額の内訳が直感と逆**: Opus 5.5で大容量Javaコードベースに4問質問したケースで、input ほぼ0%・cache read 9%・output 6%・**cache write 85%**。長い回答ではなく「初回ファイル読み込み」が請求を支配する。
- **Shuntの仕組み**: 350行超ファイルの全文readをブロックし、安価モデル(Gemini Flash)が読んで蒸留答案を返す。大容量ファイルで**82–94%削減**、162K行Javaモノレポで平均~90%。GitHub公開(~3,186 stars)。
- **Honk**: Slackで`Honk`タグを付けるとコードベースを読んでPRまで切る社内エージェント。**10日で~1,000マージ**(従来~3ヶ月ペース、7,300人の企業で)。Spotify co-CEOは決算電話で「大半のシニアエンジニアは12月から一行もコードを書いていない」と発言。
- **削減条件是付き**: Aakashの再検証ではread-heavy作業負荷では削減大、search-and-edit系ではharness側が既に最適化済みで削減がマイナスにもなる。
- 前提知識: [[concepts/kv-cache]] の課金モデル、[[concepts/coding-agents/coding-agents]] のharness最適化。上位の組織的コスト管理(Uberのツール別上限等)は [[concepts/enterprise-ai-cost-management]]。

## 深掘り

cache writeが85%という数字は「出力トークンの単価が高いからコスト管理的には出力を絞れ」という通説を否定する。Shuntがやるのは要するに *cache writeを伴う初回読み込みを、cache write単価が1桁安いモデルへ移す* arbitrageであり、コンテキスト設計([[concepts/context-engineering]])の問題ではなく請求構造の問題。Anthropicがcache write単価を動かせばShuntのトーンは一夜で崩れる——harness外部依存の典型例。

## 詳細

2026年11月、Notionが第三者推論ベンダーFireworks AIの侵害を公表([[concepts/fireworks-notion-transcript-breach]])。

- 漏洩したのはInsights機能用の **「unattributable」なNotion AIチャット文字起こし**。workspace/ユーザー識別子は付かないが、本文自体は機密を含まない保証がない。
- 影響通知が全組織で「2 members」テンプレ文言 — 実規模よりテンプレ生成ではないかと管理者から疑い。
- 原因チェーン(コミュニティ再構成、確度medium): Notionはbatch価格割引狙いで文字起こしをFireworksに「dataset」としてアップロードした可能性。**FireworksのZDRデフォルトは顧客が明示的に保持を要求したdatasetには適用されない** — つまり漏れたのは顧客側が保持を頼んだ分。
- IR批判: Fireworksは10/9時点で「顧客への影響なし」と通知していたが、実際には顧客のAnthropic APIキーがハイジャックされており、正式侵害通知は未達のまま(HN投稿者自身が発見)。別顧客はHNで知るまで無通知。
- 構造的論点: ZDRはApple Private Cloud Compute級のハードウェアアテステーションなしには検証不能([3s]、HN 50437106)。関連: [[concepts/ai-supply-chain-security]]。
