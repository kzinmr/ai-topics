## ⚡ 「2–4× less energy per token」の横に並ぶ数字が 17.2 tok/s — Unsloth の AMD NPU 対応は省エネの話ではなく実用性の死線の話

**▶ 一言要約**: Unsloth Desktop が AMD XDNA 2 NPU 対応。申告は token あたりエネルギー 2–4× 削減だが、実測表の 20B 級 MoE は 17.2 tok/s、27B は **2.0 tok/s**。NPU が本当に解決したのは電力ではなく「GPU を占有せずにローカル LLM を回せる」制約の方だ。

**詳細**（一次情報: `raw/articles/2026-11-19_unsloth_amd-npu-desktop.md`、Daniel Han (@danielhanchen) 2026-11-19 14:48 UTC の X 投稿と docs scrape）:

- **対応範囲**: Ryzen AI 300 (Strix / Krackan Point)・Ryzen AI Max (Strix Halo)・Ryzen AI 400 (Gorgon Point) 以降の XDNA 2 搭載機。将来の AMD NPU 機器は「out of the box」対応と宣言。OS は Windows 11 / Linux x64（Linux は kernel 7.0+ と `amdxdna` ドライバ、または旧 kernel + `amdxdna-dkms`、+NPU firmware と unlimited memlock）。
- **スタック**: AMD の **FastFlowLM** ランタイム + **Q4NX (4-bit)** モデルフォーマット。GGUF→Q4NX 変換は CPU で走る（→学習は任意の GPU、変換は Ryzen AI 機、という分業が可能）。Unsloth は Lemonade / FastFlowLM を自前管理し、バージョン pinned + SHA-256 検証、Lemonade server はローカル接続のみ・起動ごとに新 auth key。
- **インターフェース**: OpenAI 互換 `/v1/chat/completions` + Anthropic 互換 `/v1/messages`。`unsloth run --model ... --context-length 16384` でローカル server。reasoning / vision / tools / MCP / ローカル文書 chat 対応。

### 実測スループットが語る「省エネでは埋まらない穴」

| モデル | size | RAM | tok/s | TTFT |
|---|---|---|---|---|
| LFM3-1.7B-NPU2 | 1.5 GB | 16 GB | **40.7** | 0.12 s |
| Qwen3-VL-4B-Instruct-NPU2 | 3.9 GB | 16 GB | 20.5 | 1.05 s |
| Qwen3.5-9B-NPU2 | 7.6 GB | 32 GB | 9.5 | 1.11 s |
| Gemma4-12B-IT-NPU2 | 8.7 GB | 32 GB | 6.8 | 1.70 s |
| Qwen3.6-35B-A3B-NPU2 (MoE) | 20.6 GB | 64 GB | **17.2** | 3.13 s |
| Qwen3.8-27B-NPU2 (MTP) | 18.1 GB | 48 GB | **2.0** | 3.80 s |

- 27B dense が **2.0 tok/s** は、コーディングエージェントの実用帯（40–80 tok/s）から 20–40 倍下。MTP（multi-token prediction）を入れてこの値。
- 同価格帯の競合が埋めた穴: Apple は [[entities/apple-onnx-mlx-modelscope|MLX]] で同一メモリ帯域の M 系 Apple Silicon を 20–40 tok/s 級で運用している。AMD 側の既存受け皿 [[concepts/edge-ai|Lemonade]] の実力としても FastFlowLM/Q4NX は new path。「NPU が遅い」より「NPU を使える software stack が AMD に無かった」が正確な診断で、Unsloth がその空白を埋めた形 ([[concepts/local-llm/inference-hardware]])。
- 「GPU を占有しない」はゲーム/レンダリング/画像生成を Radeon 側へ逃がす運用を意味する。Ryzen AI Max (Strix Halo) では iGPU がシステムメモリの大きな份额を使えるので、専用 VRAM の少ない GPU より大きなモデルを載せられる ([[entities/amd-ryzen-ai-halo]])。

### API 価格と比較したときの交差点

[[comparisons/llm-api-pricing]] の実測価格で換算すると、20.6 GB の Qwen3.6-35B-A3B 級は frontier API より安い。一方 18.1 GB の Qwen3.8-27B 級は GPT-6 Luna（$0.10/$0.50 per MTok）や Haiku 5.5 と同コスト級で、しかも 2.0 tok/s。つまり **NPU ローカルがコストで勝つのは「1.5–4 GB 級 × 高頻度 × 短 context」の層に限定される**。ここが 2–4× 省エネが意味を持つ唯一のセグメントだ。

| レイヤ | 手段 | 効能 |
|---|---|---|
| ハードウェア | NPU（XDNA 2）での推論 | token あたりエネルギー 2–4× 減（vendor 申告） |
| フォーマット | GGUF→Q4NX (4-bit) 変換 | 重みサイズ圧縮。CPU 変換可。[[concepts/local-llm/model-quantization]] |
| 電力ポリシー | Power saver / Balanced / Performance / Turbo | バッテリ vs AC で最適値が変わる（FastFlowLM 既定 Performance） |
| prefill | Prefill Chunk Length（既定 4096） | 長い prompt の TTFT を短縮。context 上限とは別物 |

### 独立検証の有無と留保

- 「2–4× less energy per token」は Unsloth / AMD 双方のマーケティング記述。**測定条件（モデル・batch・電力計測点・比較 GPU 型番）は docs に記載なし**。[[concepts/ai-energy]] の既存ページが指摘するとおり、エネルギー/トークンの一次計測はデータセンター側（[[concepts/subprime-data-center-crisis]]）の文脈が中心で、クライアント NPU とローカル GPU の head-to-head は公開データがほぼ無い。
- tok/s と TTFT の表は唯一の公開数値だが、これも Unsloth 自社計測。Cerebras の「5× tokens/megawatt」もベンダー申告だったのと同じ性質（[[concepts/cerebras-disaggregated-inference]]、11/20 01:30 配信で指摘済み）。
- 「future AMD devices out of the box」は FastFlowLM と Q4NX converter 側の進捗依存（"progressively adding new models"）で、ハードウェア対応だけでは決まらない。

## 深掘り: NPU の戦略的位置づけ — CUDA moat の側面攻撃

NPU が「AI 専用エンジン」として GPU の隣に置かれるのは 2024 年頃からだが、LLM 推論の実運用で使えた例はほとんど無かった。理由は電力でも FLOPS でもなく **software stack** で、[[concepts/cuda-moat]] が示すとおり NVIDIA の優位は kernel 群と serving engine の成熟にある。AMD 側の FastFlowLM/Lemonade は 2024–2025 年に小規模コミュニティで育てられた初期ランタイムであり、Unsloth のような「すでに GGUF/quant の流通ハブになっている」プロジェクトが管理・pinned 配布を引き受けたことが実質的な参入条件を一つ下げた（[[entities/daniel-han]]、[[concepts/unsloth]] の 1-bit Inkling quant 実績が下地）。

[[concepts/ai-compute-pricing-paradox]]（Dwarkesh, 2026-07）の観点からは、NPU ローカルは「賢いモデルほど高コストになる」圧力の逃げ道として機能する可能性がある。ただし機能するのは推論内容が 20–40 tok/s で十分 = 人間の読速で消費できる層だけで、test-time compute scaling が前提になる frontier エージェントは NPU では回らない（Qwen3.8-27B の 2.0 tok/s がその上限を示す）。NPU は「クラウド請求書の下位 80% を切り出す」装置であって、[[concepts/token-economics]] の上位 20% を置き換える装置ではない。

**読者への実務示唆**: Ryzen AI 機を持っているなら、`unsloth run` で OpenAI 互換 endpoint を立て、Codex/Claude Code 系の *補完・分類・要約* サブタスクだけ NPU に逃がす構成が今のところ最もリターンが明確。27B 級を NPU で回す選択肢は 2026 年 11 月時点では実用に耐えない。
