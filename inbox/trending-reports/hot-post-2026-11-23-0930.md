# 犯人は人間ではなくAIエージェント — Together AIが公式に書き込んだたった一行の意味

朝スロット、最も鋭い物語線。昨日の夜間枠が Dragos canary 監査（推論チェーンの末尾）を扱ったので、こちらは同じ 11/21 Together AI 開示の**もう半分の側面** — 開発ツールチェーン側だ。[[concepts/dragos-inference-canary-study]] と [[concepts/zero-data-retention]] は既出なので再掲しない。

## ▶ 一言要約: 流出の犯人は人間ではなく「public repo `xorl` に credential を commit したAIコーディングエージェント」。そして Together の是正措置リストに「AIコーディングエージェントの使用に関する開発プロセスの更新」が明記された — ベンダー開示としての初出級の一節

## 詳細

- **事故の骨格**: Together AI は 2026年11月21日、6〜7月の serverless inference のプロンプトサンプル流出を告知。対象は MiniMax M3 / GLM-5.2 / Kimi K2.6 へのリクエストで、日付は **6/24・7/4・7/8・7/14** に集中。サンプルは「テスト用に認可済み」として private Hugging Face repo に保存されていた ([出典](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026))。
- **原因の主体が人間でない**: public GitHub repo **`xorl`** の開発中に、**AIコーディングエージェントが private HF repo への credential を commit** した。自動スキャンで検知され commit は revert されたが、その窓の間に無権限者が credential を取得、サンプルをダウンロードし、中に埋まっていた他サービス credential を**実際に有効性テスト**した。
- **野生のシードが実際に発火**: テストされた credential のうち **5個が Dragos の canary credential と一致**。canary 研究は「蒔いた偽証がどこかで使われたら事故確定」という設計なので、これは野生環境での陽性検出そのもの。
- **是正措置4つ**: scoped/short-lived・keyless credential / **全 PR の credential チェック** / **新規アカウントの ZDR デフォルト化** / そして **「AIコーディングエージェントの使用を規律する開発プロセスの更新」**。
- **なぜこの一行が重いか**: 既存のインシデント報告は「開発プロセスの改善」で曖昧に済ませるのが通例。Together は remediation の対象を**エージェントの使用そのもの**に限定して名指しした。wiki の [[concepts/agent-safety-incidents-open-source]] / [[concepts/artificial-contributors-open-source]] が議論してきた「AIコントリビュータの責任所在」に、ベンダー自らが運用レベルの答えを出した形。

## 深掘り: これは「AIエージェントの暴走」ではなく、90年代からある秘訣の欠落である

同じ事故を[[concepts/security-and-governance/containment-failures-are-security-basics]] の枠組みで読むと、misalignment の証拠には一行もならない。漏れたのは人間でもエージェントでも同じ構造の credential で、欠けていたのは secret scanning・スコープ最小化・PR gates という**古典的 CI/CD hygiene** だけだ。エージェントは既存の穴を人間より速く、より大量に突いただけ。

対照的に、エージェントに credential を**渡さない**方向の解決もある。[[concepts/agent-credential-leasing]]（lend、HN 116pts）は disposable VM 上のエージェントに本物の secret を常駐させず、時間制限付きで認可済みのツールアクセスだけをリースする。Together の4項目は「エージェントに secret を触らせないための従来型防御の再実装」であり、lend は「そもそも secret を届けない」 — 同じ脅威に対する二つの異なるコスト関数だ。

| 層 | Together の是正 | 既存の対応概念 |
|---|---|---|
| credential 自体 | scoped / short-lived / keyless | [[concepts/security-and-governance/agent-iam]] (NHI) |
| 混入の検知 | 全 PR で credential チェック | [[concepts/github-actions-secrets-exfiltration]] (Gheist) |
| エージェントへの受渡し | 開発プロセスの更新 | [[concepts/agent-credential-leasing]] (lend) |
| 保存側 | 新規アカウント ZDR デフォルト | [[concepts/fireworks-notion-transcript-breach]] |

## 残る未解決

「エージェントが commit した」という事実の**帰責**は未だ誰も定義していない。Together の remediation 文はエージェントを主語にしつつ、プロセス更新の対象は人間側にある。GitLost（GitHub AI agent に private repo を漏らさせる、[[concepts/security-and-governance/gitlost-agent-prompt-injection]]）や [[concepts/security-and-governance/agent-skill-supply-chain-attacks]] と同じく、エージェントは攻撃者でも被害者でもなく**単なる伝達媒体**であり、伝達媒体にプロセスを課すという構造的な居心地の悪さが残る。
