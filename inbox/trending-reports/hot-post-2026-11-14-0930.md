# 🌙 覚えておくことには睡眠が必要 — Anthropic「dreaming」で記憶の部品表が公開、wiki化は128セッションで13%→48%

**▶ 一言要約**: Anthropic が11月に公開した agent memory 部品表の核心は「dreaming」— セッションログをオフラインで再生し誤った記憶ノートを修正・昇格する処理。35万ファイル/4.2億トークンコーパスで dreaming セッション数を 2→128 に増やすと採点基準スコアが **13%→48%**、wiki+search は search 単体 53% に対し **61%**、1問あたり約20kトークン節約。

## 1. 何が部品として分解されたか

生記事: `raw/articles/anthropic.com--the-components-of-agent-memory-anthropic--90b9a347.md` / 概念ページ: [[concepts/components-of-agent-memory]]

Anthropic の定義では「agent memory」= 経験から得て**セッションをまたいで**保持される知識。重み変更(訓練)・in-context learning(単一会話)・compaction(要約で古いターンを置換)は明示的に除外。 hippocampus→neocortex の睡眠時統合との類推そのもので、学術側の概念 [[concepts/sleep-time-compute]] (Letta/UC Berkeley、arXiv:2504.13171) の first-party 実装にあたる。

部品は3つ:
1. **Memory notes** — セッション中に目立たせた事実ノート。「記憶は未来のニーズに対する予測でありうる」
2. **Dreaming** — トレースクリプトのオフライン再生。誤ノートの修正/新表現(wiki・index)構築/階層への昇格/目標に向けた成形/セッション間の欠損補完の5機能
3. **Wiki 表現** — モデルが書くリンク豊富なページ群 ([[concepts/agent-wikis]] の Karpathy 系譜、[[concepts/wiki-memory]] の Harrison Chase 定義と同一路線)

## 2. 数値が語る設計指針

| 実験 | 結果 |
|---|---|
| CL-Bench 1.0 (長期記憶) | Opus 5 が初めて学習ループを閉じた世代(Sonnet 4.6/Opus 4.7/Sonnet 5 は未達) |
| Pokémon Red 鮮度判断 | Sonnet 3.7: 413ファイル/225フォルダでバッジ1個 → Fable 5: 9ファイル+dashboard で **4バッジ** |
| Wiki scaling (~350k files, ~420M tok) | dreaming 2→128 で 13%→**48%** |
| Harvey LAB 契約書 | 文書横断判断 87% (wiki) vs 73% (search)、単文書検索では差なし |
| 目標指示型 wiki 構築 | .shared table 要約 72% → 指示書き換えリフレクションループで **100%** |
| 誤記憶修正 (Mt. Moon) | 誤った PokéCenter 位置ノートが ledge-loop を3倍に延長 → dreaming が検出・書き換え→突破 |

- 逆張りの含み: 「記録するのは失敗のみ」という固定ルールは Opus 5/4.7 の記憶ブーストを**ほぼ破壊**した。効いたのは*何のために記憶を使うか*の指示で、*どう書くか*のルールではない。
- 保存するな、が半分: 画面から再読できる状態(HP、所持品)を保存するのが最悪の手癖。保存すべきは戦略・検証済みルール。
- 失敗モードも記録: wiki がコーパスより大きくなったケースはボルヘス「論理学上の精确さ」の寓話そのもの。マップが領土を呑んだ。
- 注入層は小さい: Claude Code の auto-memory は `MEMORY.md` の先頭200行/25KBだけをインデックスとして読む。

## 3. この wiki 自身の鏡

[[concepts/agent-wikis]] に整理された「ingest 時にコンパイル、query 時に再導出しない」パターンを、この wiki は dreaming パイプライン(cron: 03:00 JST)で実践している — 昨日の run でも参照3件を統合した。Anthropic の数値が示すのは、dreaming の効きは **scaling 側(セッション数)と steering 側(目的指示)のかけ算**だという点で、lint だけ回して再生を増やさない運用は上の表の「2セッション=13%」側に留まる。関連: [[concepts/ai-memory-systems]]、[[concepts/managed-agents]]、[[concepts/claude/fable-5]]。
