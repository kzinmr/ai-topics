# 🐛 「AIバグマゲドン」は来た — 検出はタダ、修正は人間待ち

**▶ 一言要約**: NGINX HTTP/2 RCE を5チームが同時発見。AI側は1週間でApple MIEを突破、MSは7月に570パッチ — 検出が速すぎて修正が追いつかない。

## 1. 5チーム同時発見という新常態

**▶ 一言要約**: Wizが公開したNGINX HTTP/2 RCE 2件を5チームが独立に発見 — 「バグ衝突の記録か」とHN 1412p。

- **CVE-2026-123633 / CVE-2026-123007**、CVSS 4.0 = 9.2。NGINX 1.9.5（2015年）まで遡る。HTTP/2有効サーバーが対象、**225M+ サイト**が前門。
- 発見は **Wiz Research / Ikotas Labs / Metnir / Rapid7 / Xint** の5チームが独立。Xintは nginx2root.com でルートまでのフルチェーンを公開済み。
- F5への報告から**約30分で修正リリース**。应用コードが無防備でなくても、フロントドア自体が撃たれる。
- HNの疑念（leca）: 「詳細を書きすぎ。悪用まで何時間かからない」。AI起因という開示上の主張はない点はwiki側でも区別済み。
- 出典: [[concepts/nginx-http2-rce]] / [Wiz](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities) / [HN 50547374](https://news.ycombinator.com/item?id=50547374)

## 2. 検出側の速度が先に壊れた

**▶ 一言要約**: Calif 5人がClaude Mythos PreviewでApple MIEを1週間突破。MicrosoftはAI発見を理由に単月570パッチ。

| 事象 | 数字 | 含意 |
|---|---|---|
| Apple M5 MIE kernel exploit (Calif) | 5人・1週間・55ページ報告 | Appleの5年・数百億円の緩和を個人規模で回避 |
| Firefox (Mythos Preview) | 1ヶ月271件、4月423修正 = 2025年超え | ゼロデイの発見コストが崩壊 |
| Anthropic Red Team | 放置OSSで500+ critical | 「誰も保守してない」が修正側の瓶颈 |
| MS July Patch Tuesday | 570（60 critical, 3 zero-day） | AI発見をEVPが公式に理由づけ |

- 中核の読み（[[entities/antirez-com|antirez]]）: AIバグ探しは**プルーフ・オブ・ワークではない**。GPU数ではなくモデルの知能で決まり、弱いモデルほど「見つけるが当たらない」ノイズを撒く。勝者はGPU最大手ではなく、**より良いモデルに早くアクセスした方**。
- 実務への副作用: MSの Exploitability Index が死んだ。Anthropicが「Exploitation Less Likely」評価の**14件中13件**で動くPoCを生成（Tenable Narang: 「人間中心の指標だ」）。
- 出典: [[concepts/ai-vulnerability-discovery]]（raw: calif.io / mozilla / antirez / krebsonsecurity）

## 3. 攻撃者側も「エージェント+スキル」に収束

**▶ 一言要約**: RE界の重鎮が「エージェントにバイナリを投げて自作skillを使うだけ」。Ghidra をMCP経由で駆動。

- 「Slow Chronicle」(*ioma8*、20年強のキャリア) のHN 223p記事。定型作業は自律化し、人間はドメイン判断だけ残る。
- スタック: **DeepSeek v4.1 Flash**（bulk triage用・安い）+ **Ghidra + MCP bridge**、**radare2 + kuna**（遅いGhidraよりエージェント親和性が高い）、難所のみCodex。
- 注目はコスト設計: 大量バイナリのトリアージは安価モデル、難所だけフロンティア — [[concepts/model-routing]] をセキュリティ研究に適用した実例。
- 汎用コーディングエージェントを [[concepts/agent-skills]]（SKILL.md）でRE専門家に変える構造。専用RE製品を作らない。[[concepts/computer-use]] の実務的応用として [[concepts/llm-assisted-reverse-engineering]] に整理済み。
- 政策的摩擦: Anthropic の2026-10利用ポリシー運用が正当なRE（ゲームRE拒否）まで巻き込んだ文脈も同時進行（[[concepts/frontier-model-usage-policy-enforcement-2026-10]]）。
- 出典: [[concepts/llm-assisted-reverse-engineering]] / [HN 50553225](https://news.ycombinator.com/item?id=50553225)

## 4. 深夜の解釈

**▶ 一言要約**: 検出が無料になった瞬間、セキュリティのボトルネックは「モデル」から「放置OSSのメンテナ」に移った。

- 防御側の加速はまだ遅い: MS/Adobe/Cisco/Mozilla/Oracle/Google はパッチ頻度を上げただけで、修正能力そのものは人間の maintainer に依存。Anthropic の500+ criticalは「誰が直すのか」という質問を残したまま。
- Breck-McKye の「2026システム的ソフトウェア崩壊」論（HN 372p）は同じ週 cluster を「低品質部品から成る複雑系で、全体を把握できる人が誰もいない状態」と呼ぶ。AIはその加速剤であり症状でもある — ただしこれは論文集であって検証済み因果ではない。
- 生きた論点: 検出速度が開放された後、バグバウンティ・自動修正・OSS財団のどちらがボトルネックを解くのか。まだ答えが出ていない。
