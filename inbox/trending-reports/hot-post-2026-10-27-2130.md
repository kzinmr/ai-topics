# 生成はタダ、検証は重い — 2026年10月27日の逆説

今日 wiki に入った 2 件の事件ページを並べると、一つの逆説に行き着く。**AI が成果物を「生成」するコストは数ドル台に崩壊し、それを「検証」するコストがシステムの本体になった。** しかも検証側のコストは、どちらも lab の外に逃げている。

## 1. ETH 反証 — 検証が lab から fork した

**▶ 一言要約**: OpenAI が 10/25 に「ETH は偽」67ページ preprint を公開。生成側は Astra 10問題が ~$2,000・Lean 証明付きだった一方、検証側は Impagliazzo ら外部 shepherd 集団 + 有償会議に外部化された。

**詳細**:
- 主張内容は 3-SAT 厳密カウントが `2^{n/(log n)^{1/2+o(1)}}` で解けるという速度族。ETH は数百本の条件付き hardness 論文の前提なので、確定すれば graph algorithms / DB / 計算幾何の hardness 基準が全部開き直す。
- 同じリリースで 3 結果に 3 通りの公開戦略。調和解析(Kakeya 系)は「raw output を出して勝手に検証させろ」、ETH は「output + 解説集団を OpenAI が資金提供」、QFT は「共同研究者に artifact 公開を委ねる」。[[concepts/openai-eth-refutation-verification-crisis]]
- 10/24、Tao のゲストポストで **`oai-math-revised`** (github.com/mathcommunity/oai-math-revised) が始動。Nellore/Schmitt/Villar/Ward が「OpenAI の math repo は引用が不完全で読みにくい」と fork した、git-forge 型の機械証明査読層。lab がホストも編集も推薦もしない査読パイプラインが 2 日以内に生えたのが構造的な新しさ。[[concepts/ai-mathematics-theorem-proving]]
- ページ自身が記す非対称性: **検証コストが生成コストを桁で支配**し始めた。8月の Astra と違い、10月の bottleneck は shepherd の確保と会議の資金。[[concepts/station-autonomous-math-discovery]] が「発見をエージェント間で分散」したのに対し、今回は「検証を人間間で分散」した。

## 2. SGLang KV cache 漏洩 — 拒否パスがセキュリティ境界だった

**▶ 一言要約**: Cloudflare Workers AI の `@cf/zai-org/glm-5.3` で 155 件のレスポンスが他テナンのデータを返した(8/27–9/09)。全件が 681,280 トークン超の long-context。KV ページの所有権が境界だが、エンジンがそれを強制していなかった。

**詳細**:
- 二重障害。(1) 設定: context window 1,048,576 に対し prefill GPU の KV プールは 681,280 トークン分しか確保されず、しかも**プールサイズは設定値でなくエンジン起動時の残り GPU メモリから自動決定**される。整合させる機構が存在しない。(2) エンジンバグ: 超過リクエストを「拒否」したのに 1-token placeholder の KV を生成して RDMA(Mooncake)で decode に送り、decode は上書き完了と誤認、**ゼロクリアされていない stale ページ**attend して生成。[[concepts/sglang-cross-request-kv-cache-exposure]]
- 修正は二層: プールを約 2.04M トークン(≈context の 2 倍)に扩大する config 修正 + 拒否リクエストを bootstrap/alloc/transfer 前に admission queue で落とす engine 修正(upstream **SGLang #38704**、関連 #36988/#38935)。quantization や CUDA graph の変更でプールサイズが黙って変わるので、config 修正だけでは脆い。[[concepts/inference/sglang]]
- 設計教訓として最も効く一行: **rejection path は success path と同じ監査が必要**。早期リターンで下流の状態遷移が起きる箇所が全部 isolation bug の候補。canary マーカーは安い保険。

## 3. 対比表

| 観点 | ETH 反証事件 | SGLang 漏洩事件 |
|---|---|---|
| 生成側コスト | ~$2,000/10問題 (Astra 実績) | 推論 1 回あたり(価格崩壊中) [[concepts/llm-price-collapse-2026]] |
| 検証側コスト | shepherd 集団 + 有償会議 | reproduction script + canary test + upstream PR |
| 検証の実行者 | 外部数学者 (lab 外へ fork) | 研究者 Gadi Evron / 研究者が HackerOne で報告 |
| 境界の所在 | 形式化が意図した命題を捕らえているか | KV ページ所有権の台帳 |
| 未決着点 | shepherd の評価は 10/27 時点保留 | #38704 は提案段階 |

## 4. 逆説の正体

生成がタダになると、検証が唯一のスループット律速になる — これは [[concepts/test-time-compute]] の三軸(ベンチマークが測るのは中間の軸だけ)と同じ形の主張だ。math では community fork が、serving では canary test が、それぞれ「lab が制御できない検証層」の早期形態に見える。[[concepts/brooks-law-ai-agents]] の言い換えを借りれば、エージェント/モデルを増やすより、**検証の受け口を上流に用意する方が安い**。
