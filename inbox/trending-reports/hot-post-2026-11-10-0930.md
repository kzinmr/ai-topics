# 🏆 Goldmanが自社IPO主幹事を務めるAnthropicのClaude Codeを「エンジニア限定」に — バンカーから取り上げた4つの数字

**▶ 一言要約**: Goldmanは10月、Claude CodeとGitHubを約12,000人のエンジニアに限定。793ptのHNスレッドで最も鋭い指摘は「低権限コードの完全人間監査に security を依存している時点で既に負けている」(Ericson2314)。

## 1. 何が起きたか — July称賛 → October回収の4ヶ月

| 時期 | 事象 |
|---|---|
| 2026年4月 | 香港のバンカーからClaudeを除外(契約条件ベース)。JPMorganも6月に追従 |
| 2026年7月 | CIO Marco Argenti が非技術職の「vibe coding」を公開称賛 — トレーダーが作り、エンジニアが仕上げる分業 |
| 2026年10月 | 内部指引を改訂。**Claude Code と Microsoft の GitHub をエンジニア(~12,000人/全47,000人)に限定**。Strats(取引+クオンツ+工学の横断職)はアクセス維持 |
| 2026年10月26日 | Anthropic が S-1 提出、Nasdaq「ANT」で11月中に上場予定。**Goldman は Morgan Stanley と並び主幹事** |

- 対象は「自律的にコードを書き実行するサードパーティ製エージェント」。行内マルチモデルAIアシスタントは全行維持 — 禁止の対象はエージェント型の自律実行に絞られている。
- トレーダーはエージェントで顧客フロー監視・マーケットポジション・資料作成を行っていた。Bloombergの情報筋によれば「生産性」もレビューの一因。
- 生記事: `raw/articles/2026-11-09_stateofai_goldman-sachs-pulls-claude-code.md`(原典はBloomberg、State of AIは二次配信。HN 50415628)

## 2. なぜ取引フロアは危険か — コストの実数

- Claude Codeは使用者と同等のアクセス権でファイル読み・コード書き・実行を行う。エンジニアのコードは review → testing → deployment control を通るが、トレーダーが組んだ顧客フロー監視スクリプトは「日常利用されるのに何も通らない」。
- 規制当局が求める情報バリア(deal担当とトレーダーの分離)を前提にGoldmanの行内AIプラットフォームは設計されている。エージェントで作ったツールはその前提なしに動く。
- コストの裏付け: [[entities/anthropic]] のS-1開示では内部Claude利用を小売価格で約$300k/人相当に計上(Business Insider、HN 50339494)。Accentureは従業員1人あたり**$29/月**のClaude枠に限定、Amazonは社員が無意味タスクでエージェントを回して順位を上げる leaderboard を閉鎖した。
- 対照例: Barclaysは10月に「年内に開発者の半分がClaude Codeを利用」と発表し、3週間後に5,000人の人員削減へ開発者を含めた。同じ「エンジニア限定」でもGoldmanはリスク抑制、Barclaysは人員削減の手段。

## 3. HNスレッドの分岐 — 「禁止」は正しい解ではない

**▶ 一言要約**: 禁止を支持する声も「人間監査に依存するsecurityは既に破綻」という反技術的指摘も、結論は同じ——実行環境の分離([[concepts/sandbox]])に逃げただけ。

| 主張者 | 主張 |
|---|---|
| CharlieDigital | 「読めない人間が書いた未レビューコードを取引フロアに置くのは最悪。情報バリアだけで禁止の正当化になる」→ 同一人物からの反論「開発者もエージェントコードを読めなくなっている」 |
| Ericson2314 | 「低権限コードの完全人間監査にsecurityを依存している時点で既に負けている。正解はバンカーが自傷できないプログラミング環境を設計すること」 |
| neya | 内部財務を学習したモデルが他所で使えればインサイダー取引 |
| theptip | ローカル実行のClaude Codeから、サンドボックス化された [[concepts/managed-agents]] への移行が中期的帰結 |

Ericson2314 の立場は本wikiの[[concepts/sandbox]]系統(サンドボックス階層化)と同じ結論に着地する。リスクの所在を「誰が使うか」ではなく「どこで実行されるか」に移す設計だ。Goldmanの措置は前者で押さえており、HNの評価は「判断は正しく、やり方は誤り」に寄っている(State of AI の編集部見解も同じ)。

## 4. 本wikiの既存知見との接続

- [[concepts/ai-adoption-barbell]]: 10-70-20分割(5-10% power user / 70%非利用者 / 20%拙劣利用者)の10%側に相当するのが、Goldmanがアクセスを残したstrats+エンジニアである。「全行配布で採用率を上げる」戦略の失敗が、配布を絞った今回と同じ会社で同時進行している。トークン消費も10%のユーザーが90%を消費する集中度を示す。
- [[concepts/agent-model-drift]]: Goldmanの撤回理由は個別インシデントではなく「生産性とリスクのレビュー」= エージェント挙動を証明するアーティファクトが存在しないこと。前回の夜間版で扱った「観測可能性の欠如」が、対策の形を **instrument ではなく revoke** に傾かせている。検出不能なエージェントにはアクセス撤回がデフォルト応答になる、という予測が今回の一件で裏付けられた。
- [[concepts/claude-code/claude-code-sandboxing]]: Apiiro が報告した「Don't Ask Again」による資格情報漏洩(公開GitHub上で `.claude/settings.local.json` 1,122件、HN 50407882)は、Goldman型の禁止を強化する側に働く材料。エージェントが書いたコードだけでなく、エージェントが残した設定ファイルが情報漏洩路になる。

## 残る問い

Goldmanのトレーダーが必要としていた業務(顧客フロー監視・ポジション・資料作成)の置き換え先がBloomberg報道に一切登場していない。取り上げただけで代替を示さない回収は、[[concepts/ai-slop-productivity-paradox]] で論じられる「採用指標だけ上げて実益を出さない」パターンと区別がつかない。Anthropic上場(Nasdaq「ANT」、11月中)までに後任の製品が発表されるかが検証点。
