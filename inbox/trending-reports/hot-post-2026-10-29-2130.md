# 🔒 「AIを使うな」では足りない — MicroZig が禁じた"思考の出所"という検証不能な線引き

**▶ 一言要約**: MicroZig が2026-10-28に導入した No-AI 規程は、要約・ brainstorming ・誤字修正まで禁止し、さらに「LLM使用を語ること」自体を禁じた — 検出不能な「認知的出所」を律する、史上初の規範のみで機能するAI禁令。

## 事実

- Zig Embedded Group の埋め込みプロジェクト MicroZig が CoC に "Strict No LLM / No AI Policy" を追加(発効 2026-10-28、HN 2026-10-29 で ~51pts)。管理者は Matthew Knight と Felix Queißner の2名のみ。
- 禁止対象はコードと散文のみではない([wiki/concepts/microzig-no-ai-policy.md]):

| 行為 | Zig 本体(2026-04) | MicroZig(2026-10) |
|---|---|---|
| LLM生成コード/散文 | 禁止 | 禁止 |
| LLM出力の言い換え | 規定なし | **禁止** |
| 誤字・文法修正 | 規定なし | **禁止** |
| brainstorming後に人間が書いた出力 | 規定なし | **禁止** |
| LLMでのバグ発見 | 規定なし | **禁止** |
| LLM使用の言及 | 規定なし | **禁止** |

- 翻訳も禁止だが、母語での投稿は「歓迎」と明記 — 読む側が各自の翻訳ツールを持て、という逆転の設計。
- 典拠として Asimov の短編 *"Profession"* を引用。

## 解釈(夜間だからこそ対抗的に読む)

1. **禁止の実体は2条項だけ**。コード検出は既存ツールで可能だが、「言い換え禁止」「brainstorming 結果の共有禁止」はどんなツールでも検証できない。つまりこの規程の作動機構は技術ではなく**規範**であり、自己申告と管理者2名の判断に依存する。
2. **「使用を語るな」条項が議論を封鎖する**。同じ CoC が「本規程の議論・違反告発」も禁じているため、運用トラブルが可視化されない。他の全 AI 禁止ポリシー([wiki/concepts/llm-policies-open-source.md]、[wiki/concepts/ai-code-provenance-in-open-source.md])との決定的差はここ。
3. **Zig 禁令の商業的歪みが小規模プロジェクトで解消される**。Zig の LLM 貢献禁止は Bun が `bun compile` の 4x 高速化(並列意味解析+複数 codegen unit)を upstream できない原因になっている([wiki/concepts/zig.md])。管理者2名・レジスタ書き込み错误が現場故障に直結する埋め込み HAL は、禁令が最も安く、最も正当化しやすい環境。
4. **反論**: 完全禁止が選抜するのは「無支援で働けるほど裕福か若い貢献者」だけで、保護すべきメンテナ供給網を自ら縮める([wiki/concepts/anti-ai-arguments-are-conservative-arguments.md]、[wiki/concepts/ai-slop.md])。判定基準は2027年までの貢献者数と PR レビュー遅延 — MicroZig が安定し類似の埋め込みプロジェクトが AI-slop PR に淹れるならテンプレ化し、逆なら niche のまま。

## 対比: 同じく今週出た別ベクトルの「AIの隠蔽」

同じ週に対極の事例が揃った。MicroZig は人間の AI 利用を隠すことを禁じるが、[[concepts/weight-compiled-computers]] の Qwenputer(Qwen3.5-4B に RV32I RISC-V CPU を重みにコンパイル、L4 1枚で ~3,200 CPU-tokens/sec、HN 532pts)は、モデルが Gated DeltaNet の状態行というトークンストリーム外のチャネルで計算し、chain-of-thought モニタリングを回避しうることを示した。人間側の出所検証不能性 vs モデル側の計算隠蔽 — 2026年10月は「検証不能な中間層」が両側から顕在化した月になるかもしれない。関連: [[concepts/sleep-time-compute]](オフライン計算の隠蔽ではなく前倒し)。
